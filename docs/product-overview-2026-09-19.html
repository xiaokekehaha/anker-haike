05算法与原理

每节按「问题 → 方案与公式 → 为什么这么做」。所有算法都是确定性的或有确定性校验包裹；模型输出在这里只是输入之一。

5.1 检索：多变体 RRF 融合与跨库交错knowledge/search.py

问题

手册库、工单库、本地 FAQ、重排模型的分值量纲互不可比（WeKnora 内部 RRF ≈ 0.016、FAQ Dice 0.3–1、rerank 0–1），不能按原始分混排。

方案

一律用名次而不是分值。同库多变体用 Reciprocal Rank Fusion 合并；跨库再按库内名次交错，同名次按来源可信度破平；反证工单永远排最后。

score(d) = Σ_{q ∈ Q, d ∈ R_q}  1 / (k + rank_q(d))          k = 60

排序键 = (counter_evidence, −score)                     反证工单排在正证之后
跨库破平 = kb_manual(0) > kb_faq(1) > kb_tickets(2)
状态合并 = 任一 ok → ok ；全部或部分 unavailable → unavailable ；否则 no_match

查询变体不调模型：只用已审核同义词表把口语替换为规范词（「不吸」→「吸力下降」），单点替换各一条加全替换一条，断言不引入原句没有的型号或数字；请求数 ≤ 变体数 × 库数 ≤ 6。

product_state检索前允许的知识条目
confirmed_skusku_list ∋ sku　∪　scope=category_generic ∧ 同品类
category_only仅 scope=category_generic ∧ 同品类
unknown空集，不发请求。空 knowledge_ids 在 WeKnora 等于不过滤，禁止退化为整库搜索

同一函数同时决定进 synthesize 的证据顺序与评测 top-k，保证「评测跑的就是线上链路」。多变体 / 重排 / FAQ / 改写 / 充分性评估当前全部默认关闭，每项凭评测报告单独开启。

5.2 本地 FAQ 匹配：字符二元组 Diceknowledge/faq.py

问题

WeKnora v0.8.0 对 FAQ 库的检索接口实测返回空；FAQ 条目少且品类通用。

方案

适配器侧确定性匹配。先去标点、去产品词与口语虚词（它们只会稀释症状相似度），再算二元组 Dice；子串包含时给高基线分。

若 s ⊂ q 或 q ⊂ s :   sim = 0.85 + 0.15 · min(|q|,|s|) / max(|q|,|s|)
否则 :                sim = 2 · |B(q) ∩ B(s)| / (|B(q)| + |B(s)|)        B(t) = t 的字符二元组集合

阈值 0.3 以下不返回（避免「无知识」样例泄漏）；只在会话品类内匹配

5.3 证据充分性评估与有界补查knowledge/context.py · diagnose/grade.py · diagnose/rewrite.py

问题

单轮检索可能不足；无界 Agentic RAG 会不停改写重查，延迟与幻觉都不可控。

方案

两层预算 + 至多一次受控补查。候选池与最终证据分离：评分只标记质量不删候选；改写只改检索表达不产生业务事实。

证据选择：按 (轮次, 来源) 分组后 zip_longest 交错，来源优先 kb_manual < kb_faq < fault_card < kb_tickets
          反证至少保留 1 个代表；不按一次 grade 的 irrelevant 删除证据

字符预算（context_chars = 5000，item_chars = 800）：
  allowance_i = min( item_chars, (max_chars − 已用 − Σ_{j ≥ i} header_j) / (n − i) )
  正文按锚点居中截取；被挤掉者记 excluded[item_limit | char_limit | empty_content]

充分性评估（轻量模型，≤ 12 条）：
  逐条 verdict ∈ {relevant, irrelevant, unsure}；coverage ∈ {sufficient, insufficient, none}
  missing_symptoms 只能从「有效症状」逐字选择
  保守规则：sufficient 但无 relevant → insufficient；只有反证工单 relevant → insufficient

受控改写：Schema 仅 {query}；拒绝 空 / 超长 / 与原句相同 / 改变否定数 / 新增型号·错误码·数值·部件·原因词
          第二轮预算 3000 ms，剩余 < 3 s 跳过

5.4 症状问诊：最小分裂判别树conversation/taxonomy.py · diagnose/decision.py

问题

口语常映射不到唯一故障族（「充不进电」可能是输出也可能是自身回充）；模型自由追问会复读、跑题、无限循环。

方案

确定性判别树，问题来自配置而非模型。每题按 yes / no 切分候选，选把候选切得最均匀的题；无题可问就让用户在剩余现象里多选。

候选集 C 初始 = 该品类全部故障族
可用判别题 D 须满足  C ⊆ yes(D) ∪ no(D)  且两侧非空

D* = argmax_D  min( |C ∩ yes(D)| , |C ∩ no(D)| )        最大化最坏情况的缩小量
回答后  C ← C ∩ splits[answer]

无可用题且 |C| > 1 → 多选 symptom_selection
首问：|C| ≤ 6 且尚无回答 → 直接多选（4/1 切分的是非题期望信息量接近零且必再追一问）
终止条件结果
连续无进展回答 ≥ 2全为「不知道」→ answers_unavailable，否则 no_progress → R7
总回答数 ≥ 8clarification_budget_exhausted → R7
有回答但候选为空evidence_conflict → 升级
剩余候选共享同一组适用计划不再问，直接 continue

「进展」= 候选集合变化。新增可归一的症状事实重置连续无进展窗口但不重置总预算；归一不到任何故障族的补充记为 unmapped 并计入预算，否则「每次补充都清窗口」会让同一问题重复到永远。规则与模型给出的症状码不一致时记 disagreement，不静默采用。

5.5 下一动作决策：证据驱动的候选序列diagnose/decision.py::decide_next · plans/models.py::observation_gate

问题

模型自由生成的「下一步」没有来源、可能重复已做步骤、可能在有风险时继续操作。

方案

纯函数：不调模型、不写库、不发事件。输出 NextAction(kind ∈ {ask, step, resolved, handoff_offer, safety_stop, pause}, reason, basis)。

  1. 风险证据（allowed_operations=false / R4）→ safety_stop
  2. 用户要求人工（R3）→ handoff_offer
  3. 上一步反馈 solved → resolved
  4. 用户暂停 / 纯投诉 / 资源缺失待答 / 请求解释 → pause 或 ask
  5. 候选序列 = plans_ranked 中 confidence ≥ 0.3 且未耗尽者（保持模型排序） ＋ 观察门已满足的解锁计划。逐个：excluded 跳过；missing 记第一个可问观察（同一观察最多问 2 次）；有未执行步骤记第一个可发布步骤；解锁计划与已记录症状码不相交先问一次范围。取序号最小的可行动作，前面的步骤不被后面的问题抢先
  6. 有阻碍 / 资源缺失 / 连续跳过 ≥ 3 / 情绪策略要求少步骤 → 资源复核或 pause
  7. 无支持的下一动作 → handoff_offer（observation_unavailable / no_supported_followup / knowledge_coverage_missing）
observation_gate(known):
  excluded_by_observations 命中          → excluded
  requires_observations 中有未知         → missing（列出缺失 id）
  已知但不在允许选项                     → excluded
  否则                                   → ok
未观察到不能当作阴性：只会让计划「缺失」，不会让它「排除」或「满足」

R1–R8 是对外兼容 / 观测层的规则码映射，真实结束原因在 next_action.reason。

5.6 读图：一次可信的测量images/quality.py · diagnose/vision.py

问题

视觉模型无法自知其无知。公开实验中亮度降到 0.15 倍时 VLM 准确率从 0.99 掉到 0.22，而自报置信度仍稳定在 0.87–0.90，错误检测 AUROC ≈ 0.50。最该拦的图恰好是模型看不出自己看不见的那些。

方案

四层：像素层门控（不调模型）→ describe-first 结构化输出 → 铭牌裁剪复看交叉核对 → 图文冲突由代码比对。

指标定义rejectmarginal为什么
focus长边归一 1024 → autocontrast → 水平梯度 |I(x+1) − I(x)| 的 99.5 分位—< 12高分位而非均值：大片纯色的清晰图均值也低。合成图阈值不迁移，故只做软阈值
luma_p95灰度直方图 95 分位< 60< 110不用中位数：深色机身正常曝光中位数 64 但 p95 有 204；真欠曝两个数一起塌
clipped亮度 ≥ 250 像素占比> 0.5> 0.3过曝
short_edge原图短边像素< 300< 480拍太远 / 截图裁剪

reject 直接发补拍卡，一次模型都不调；marginal 交模型再看，两边都说不行才判不可用；多图取最好的一张。

describe-first：字段顺序即生成顺序
  observations[≤5 条可见事实] → findings[part, phenomenon, severity, cell] → model_hint
  词表区分「其他」（看清了但不在表内）与「不可辨」（看不出）——合并会把未知当成已知的异常

铭牌复看（触发条件是「有型号」而不是「读不清」——校验开关不能握在被校验者手里）：
  按模型指认的九宫格 cell 裁剪放大再读一次
  两次一致                 → verified=True，可自动锁 SKU
  两次不一致               → 取裁剪结果，verified=False，让用户确认
  裁剪图读不出（单图）     → 全图那次的自信答案不可信，清空回到「不知道」
  无法复看                 → 保留原值，verified=False

效果：三家模型铭牌读出率 67% → 100 / 100 / 67；主模型综合 65% → 93%；编造路径被堵死

5.7 安全规则与否定语义rules/service.py::_mask_negated

问题

视觉模型会把「没看到危险」也写成观察项：「未见冒烟烧焦鼓包漏液火花」。子串匹配读不出否定，正常的滚刷缠绕照片因此被判 R4 安全风险、排障中断。

方案

只承认一种否定形态：否定词后紧跟一串安全词，词间只允许连接词。跨过标点或任何实义字符即视为新陈述继续按命中处理。

「未见 冒烟 、 烧焦 、 鼓包」   → 三个安全词全部被遮盖
「无线充电座冒烟」              → 「无」后面是「线」，不是安全词：不算否定，命中
「未见冒烟，滚刷烧焦」          → 逗号断句：只遮住「冒烟」，「烧焦」命中

安全判定宁可误报不可漏报，所以判否定的条件比判命中严得多
词表按 mtime 热加载；检查点覆盖 用户文本 / 图片观察 / 动作 / 备注 四个来源

5.8 保修政策引擎policy/engine.py · config/policy/*.yaml

问题

保修判定要可解释、可追溯到条款原文，且不在没有依据的区域外推。

方案

纯函数、无 IO：冻结的规则包 + 输入完全决定结果，trace_id 由规则、条款、输入的哈希决定，同输入同结果。

  1. 别名归一（美国 → US，Amazon → platform_store）
  2. 缺任一必填（购买区域 / 使用区域 / 渠道 / 购买日期）→ needs_human(missing_inputs)
  3. 三级匹配：品类 ∧ 购买区域 ∧ 渠道 ∧ 系列子串 ∧ 部件类 全满足的规则中取 priority 最大者：品类兜底 10 < 系列 20 < 部件 / 系列例外 30；无匹配 → needs_human(no_policy_matched)
  4. warranty_end = purchase_date + months（按月加、日期夹到月末）；lifetime 无到期日；none 恒不在保。within_warranty = purchase_date ≤ today ≤ warranty_end
  5. exclusions / cross_region：每条 when 全满足即命中，效果 no_free_remedy 或 needs_human，附条款引用
  6. 处置阶梯 parts → repair → replace → refund → paid_repair：eligible = 条件全满足 ∧ ¬(no_free_remedy ∧ 公司承担)；auto_allowed = eligible ∧ 规则允许 ∧ ¬needs_human

条款库每条带 source_url、采集日期与原文 quote。只写 US 站：页面原文明示保修期因国家而异，其他区域没有采集到等价来源，一律转人工。系列（GaNPrime / Prime / MagGo → 24 个月）按产品名子串认，因为系列在目录里没有独立字段。

5.9 上下文预算context/builder.py · context/budget.py

问题

多轮会话把历史、事实、证据全塞进提示词会超窗或挤掉当前输入；不同任务的输入预算不同。

方案

跨厂商 token 估算显式留余量；按任务给预算；超预算时按固定顺序让步并记录分块统计。

tokens(text)   = ceil( |tiktoken o200k_base 编码| × 1.25 )
message_tokens = tokens + 8
B(task)        = input_budgets[task]（intake 16000）或 max_input_tokens 8000
                 − 256 − tokens(输出 schema JSON) − tokens(附加指令)
used           = system + authority(状态投影) + current + history

超预算让步顺序：丢历史摘录缓存 → 当前长文本头尾各留、中间省略（≥ 200 字符）→ 抛 ContextBudgetExceeded
路由前再校验：text + 每图 16k + output_tokens ≤ 模型 context_window
状态投影只含模型该看的字段；身份、证据、业务状态留在存储

5.10 模型路由、降级与容量models/router.py · config/models.yaml

每个任务一条模型链（如 diagnose.synthesize: deepseek → qwen-max → glm-v），按模型能力选结构化方法（native json_schema / json_object + schema 提示 / 工具调用），统一 Pydantic 校验。ModelRouter 是唯一重试层，厂商 SDK 重试关闭。

失败类型处理
超时 / 5xx / schema 校验失败同模型重试 1 次（schema 失败带错误提示），再失败换下一家
429同模型最多 3 次，退避 1 / 2 / 4 s + [0, 0.5) s 抖动
拒答 / 内容过滤不重试，直接换下一家
能力不匹配 / 别名未配置路由前跳过，记 skipped，不计入重试
预算单次超时 = min(模型 timeout, 剩余预算)；剩余不足以再调一次即停止
全局容量有界门 max_in_flight = 50，满则立即返回 error(recoverable=true)，不排队

5.11 模型选型 bake-off 裁决bakeoff/runner.py::judge · bakeoff/scoring.py

先过硬门（如铭牌不编造率 100%），再过 schema 通过率、准确率、P50 延迟门槛；达标者按综合成本排序。准确率只作门槛不参与排序，因为聚合准确率会抹平「失效方式」的差别。

key(c) = latency_p50 / latency_cap  +  cost_cny_per_call × 100         最小者为主模型
备用须来自另一家厂商，且 schema_pass ≥ 备用门槛 ∧ accuracy ≥ 主 − Δ ∧ latency ≤ 主 × ratio

评分函数按任务对 expect 规则逐项打 0–1：
  synthesize：top1 命中 ∧ 每个假设都有 evidence_ids
  reply.stream：≤ 200 字 ∧ 无代码块 ∧ 不出现「可保 / 免费维修」等资格结论词

5.12 评测口径knowledge/eval.py · evaluation/semantic.py · analytics/derive.py

  • 检索：hit@k（expected_doc_ids 任一在 top-k）、precision@k、leak（无知识样例却返回命中）、scope_leak（命中当前作用域不该看见的文档），按 tag 分组。
  • 语义：独立文本金标经与线上相同的 interpret_turn，逐字段准确率；金标绝不进入解释器状态或提示词。
  • 会话结局：只看 checkpoint 权威状态 + done.reason，不看事件文本；升级原因分系统失败 {R1, R1b, R1c, R2, R5, R7} 与用户 / 政策决定 {R3, R4, R8}，解决率只把前者算失败。
