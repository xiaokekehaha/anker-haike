# T36 条件诊断卡片的问题与修改方案

日期：2026-10-10。用户要求：记录截图中的问题，检查应如何修改；本轮产出为问题记录、代码诊断和修改方案。

## 问题与证据

T36 客户使用荷兰语，产品为 S1 Pro / T2080A。客户说吸尘时噪音很大，所有滤网和刷子都已更换、全部清洁后仍未改善，担心吸尘电机会坏掉。电机损坏尚未确认。

用户提供的截图中，`rv-0341` 整段内容作为一张操作卡发布：

- 拆下滚刷和盖后若声音消失，可能与滚刷有关。
- 拆下后声音仍在且像 chirping，再尝试拖地模式；该模式下声音消失可能与万向轮经过瓷砖缝有关。
- 末尾说明配件或换机需要核保。
- 卡片反馈只有「解决了 / 还没解决 / 做不到、跳过」，预期结果仍是确认问题是否解决。

当前截图的换机承诺已经受核保约束。此前回放中的重复滤网检查不能算作这张截图的已证实问题。拆滚刷测试也不等于重复更换刷子：更换耗材后，滚刷盖和安装位置仍可能需要定位。

## 期望行为

1. 承接已知型号、吸尘时噪音和已做的清洁、更换，不重复问已知信息，也不宣布电机损坏。
2. 当声音特征会影响后续检查时，只问缺失的声音特征；客户描述未知，不能默认属于 chirping。
3. 一张卡只包含当前适用的一个诊断测试，说明测试目的和观察项。
4. 反馈记录「声音消失 / 仍在 / 无法测试」等具体结果，据此选择后续检查；症状暂时消失不自动代表设备已修复。
5. 诊断测试中「声音消失」与维修操作中「问题解决」分开；未测试、跳过或没有回答不能当已执行。
6. 仅当前提和上一步观察结果支持时，给出拖地模式测试；后续售后流程继续核资格，不提前承诺寄件或换机。
7. 对客语言与客户语言一致；翻译后的展示文案不应作为稳定的流程标识。

## 代码诊断

定义：诊断测试是为了收集观察、定位原因的操作；修复操作是以恢复正常使用为目标的操作。拆下滚刷后声音消失是诊断结果，不等于设备已恢复正常使用。

已完整读取 `official/qa_index.py`、`plans/{qa,models,library}.py`、`guide/{steps,verify}.py`、`contracts/haike_contracts/{common,actions,events}.py` 和 `frontend/src/components/StepCard.tsx`。

| 环节 | 已核实的现状 | 对 T36 的影响 |
| --- | --- | --- |
| `official/qa_index.py:split_steps/build_guide` | 主要识别编号步骤；没有编号时整段生成一个 Step | `rv-0341` 的多个 If 条件和测试合在一起 |
| `plans/qa.py:plan_of` | action 统一使用 solved/not_solved；没有拆出来的问题就没有 options/branches | T36 生成一个 action，branches 为空 |
| `plans/qa.py:step_condition` | 仅识别段首 If；续接上一步结果的条件不作为场景条件 | 不能拿此函数解析 T36 正文内部的声音变化和 chirping 条件 |
| `guide/steps.py:prepare_step` | 发布计划所指步骤的正文，没有运行时语义拆分；`customer_text` 只做售后话术过滤和人称改写 | 弹窗收到的已经是一整段操作正文，前端排序无法恢复条件关系 |

| `contracts/common.py` | StepAnswer 有 option/text/unavailable；当前卡片没有区分普通问答与含操作的诊断测试 | 可复用回答通道，但需补足测试正文展示、执行记录和未知结果的语义 |

本轮只追踪上述路径。`sessions/graph.py`、快照投影和历史重放尚未逐个完整读取，列入实施前阅读清单；不能仅依据其他方案描述直接编辑。

调查期间共享工作区的 `qa_index.py` / `plans/qa.py` 又加入了 `split_at` / `step_parts`：可按审核锚点将原段拆成前后两步，后半步 ID 为 `s{pos}b`。这是其他会话的修改，本轮未触碰。复现时 T36 仍是一张卡；文本拆分机制本身没有补齐诊断结果、完整条件路由和未知答案处理。

## 最小复现

在临时测试中调用真实 `get_qa_index → plan_of → customer_text`，断言一张 action 不应同时包含拆刷测试和条件拖地测试：

```python
guide = get_qa_index().guides["rv-0341"]
plan, evidence = plan_of(guide, "t36-probe")
for step in plan["steps"]:
    text = customer_text(evidence[step["instruction_src"].removeprefix("evidence:")]["snippet"])
    assert not (
        step["kind"] == "action"
        and "removing the roller brush and cover" in text
        and "try using the mopping mode" in text
    )
```

执行命令：在 `orchestrator/` 下运行 `uv run pytest -q tests/test_tmp_t36_card_20261010.py`。

结果：首次 `1 failed in 0.43s`，错误为：

```text
s1: multiple conditional tests share one action card
branches={}
next_on={'solved': 'DONE', 'not_solved': 'EXHAUSTED', 'cannot_do': 'EXHAUSTED'}
```

再通过真实 `apply_feedback` 做两个探针，结果为 `1 failed, 2 passed in 0.78s`：

```text
not_solved: outcome=reassess, observation=None, executed=1, plan_cursor=None
solved: outcome=done, observation=None
```

静态计划中 cannot_do 指向 EXHAUSTED，但实际运行时会记录阻碍并重新评估，不能把它描述为“跳过就直接走售后”。同样，EXHAUSTED 触发重新评估，不直接保证核保；错误在于单个笼统反馈已经耗尽整个诊断计划、没有留下分支所需的观察。

这是知识转换和反馈推进层的确定性复现，没有调用真实模型、知识库或设备，也没有验证截图所在服务的部署版本。临时测试诊断后删除；上面的复现逻辑保留在本记录中。

## 建议流程

前轮建议“先确认声音特征”不是固定必经步骤。只有缺失事实会改变当前操作时才问；原文已说明吸尘时发生，不再重复询问是否发生在吸尘时。

| 交互 | 显示内容和结果 | 后续 |
| --- | --- | --- |
| 承接事实 | 已换滤网/刷子、已清洁仍有噪音；电机故障尚未确认 | 给当前适用的定位检查或必要澄清 |
| 滚刷隔离测试 | 展示一次完整测试，结果为声音消失 / 声音仍在 / 未测试或无法判断 | 消失：记录滚刷/盖相关候选原因并重新评估；仍在：判断下一测试的声音条件；未知：等待补答或处理阻碍 |
| 必要的声音澄清 | 仅当尚不知道是否符合源文的 chirping 条件时询问 | 明确符合才允许下一项拖地测试；不符合则评估其他适用资料；未知不能默认符合 |
| 拖地模式测试 | 展示当前适用的这一项测试，结果为声音消失 / 声音仍在 / 未测试或无法判断 | 消失：保留轮子/地面关系的候选解释并重新评估；仍在：评估后续售后或其他适用检查；未知不耗尽计划 |
| 后续处理 | 根据真实观察、尚未完成的检查和资格选取下一动作 | 按现有售后 SOP 核资格和交接；不承诺寄件或换机 |

测试的具体操作正文必须来自审核资料。`rv-0341` 含诊断条件，`rv-0339` / 对应官方文章含拆下滚刷和盖、以 single sweep mode 运行一次的操作说明。若合并使用两条资料，必须保留各自引用；不能凭内部 If 句子自行补造操作模式、时长或拆装办法。

滚刷隔离测试的中文显示示例（正式对客文案应为荷兰语）：

> 检查滚刷和滚刷盖是否与噪音有关。您已经更换过刷子，这次通过拆下滚刷和盖后的声音变化进一步定位来源。请按官方步骤完成一次测试，并反馈声音的变化。
>
> 声音消失了 / 声音仍然存在 / 未测试或无法判断

“声音消失”不能调用当前 action 的 solved 分支：设备在拆去部件后的诊断状态中安静，不能由此直接结束整个问题。

## 修改方案与顺序

### 1. 复用 T26 的审核步骤能力，表达多步骤和明确结果

与 `docs/planning/2026-10-10-1656_t26-conditional-troubleshooting/plan.md` 共用一段多步骤、明确回答、未知待确认和发布前条件检查的能力。该文档为已有方案，本轮没有新建或改动 planning 文件。

扩展审核表示，至少保存每个交互的稳定标识、来源、正文、测试目的、结果选项、选项到后续交互的关系、所需设备和明确适用条件。运行时按照编译好的结构执行，不按 T36 或 rv-0341 编号写业务分支；按来源条目编写审核数据属于知识内容配置。

文本拆分锚点可用于定位来源，但不能作为完整解决方案。它还不能表达“拆刷后仍吵且声音为 chirping 才测拖地”，也不能把“声音消失”与“问题解决”分开。

### 2. 在现有回答通道中补足诊断测试语义

优先复用 question + StepAnswer 的选择和短答通道，明确标记哪些问答含一项诊断测试。前端应显示“检查并反馈”、完整操作正文、测试目的及结果选项；普通背景问题仍只是回答问题。无需另外增加 HTTP 动作种类。

执行和观察分别记账：

- 客户明确完成了拆件、运行等诊断测试时，记录该测试执行和具体观察；实际操作计数只增加一次，继续受现有操作上限约束。
- 普通事实问答、未测试、无法判断和无法操作不计执行；不能因为复用 question 就丢掉真实测试执行历史。
- 声音消失、声音仍在只记录观察并选下一步，均不能等价于 solved/not_solved。
- 短答保留；只有明确归一到合法结果时才选下一步。“还是有问题”、矛盾或未识别文字不能默认替代某个观察结果。
- 未知结果保留当前待确认状态，不把卡片折叠成已完成，不用于历史去重，也不触发计划耗尽；允许暂停、恢复或明确请求人工。

只修改按钮文字而继续发送 solved/not_solved，会保留当前错误。仅把含操作的正文改成 question，也会因当前隐藏 instruction、不计执行而丢失必要信息。

### 3. 发布前检查条件，区分诊断结果和修复终点

声音仍在与 chirping 是两个独立条件，只有明确成立才能发布对应拖地测试。未知时等待补充；声音特征不符合时评估其他候选资料。

使用带原因的重新评估结果，区分“定位到一个候选部件”和“全部适用检查完成”。滚刷或轮子候选解释不直接标记设备修复，也不自动确认硬件损坏。

刷新、历史重放、事实预填和用户更正都采用同一条件规则。旧单卡的 not_solved 不能补出新的多个观察；审核内容和计划版本变化时，旧待答卡应失效并重新确认。原段来源、媒体、拆分步骤 ID 和去重键需要独立绑定，不能继续只用 s<number> 下标反查原段。

### 4. 契约和展示随运行时一起修改

先在 `contracts/haike_contracts/` 定义前端所需的最小字段，再执行 `make contracts`。按钮的稳定结果标识与显示文案分开；展示语言改变不能改变选项路由。

语言一致性单列为表现问题：当前正文固定使用官方英文，按钮固定中文。根据客户语言生成经来源约束的展示文案，仍保留原文证据。诊断路径无需为了多语言引入另一套状态机。

## 验收

| 场景 | 必须满足 |
| --- | --- |
| 原始 T36，没有声音类型和测试结果 | 承接已清洁/已换件；一次只显示一项适用测试或必要澄清；不猜电机损坏 |
| 拆刷后声音消失 | 写入具体观察和实际测试记录；候选为滚刷/盖相关，问题仍可继续处理；不直接 DONE |
| 拆刷后仍响且符合 chirping | 允许显示单独的拖地测试 |
| 拆刷后仍响但未知/不符合 chirping | 不靠默认边发布拖地测试，分别等待或重评其他适用资料 |
| 拖地模式下声音消失 | 记录具体模式下的变化，保留轮子/地面关系的候选解释；不宣称已修复电机 |
| 拖地测试后仍响 | 基于适用检查和事实评估后续处理，资格未核前没有寄件承诺 |
| 未测试、无法判断、非明确短答、矛盾、更正 | 不计实际执行、不默认选边、不消费待答步骤；更正后重新检查条件 |
| 只完成了一项测试 | 不把整个源段的其他测试记成已完成 |
| 刷新、切换问题、动作重试、旧卡反馈 | 保持同一明确结果路径和幂等；不跨问题复用、不接受旧卡控制新步骤 |
| 客户语言为荷兰语 | 正文、标题、结果按钮语言一致，结果标识和来源保持稳定 |
| 非 T36 的合成条件测试段落 | 同一编译和反馈能力可运行，证明没有工单特判 |

建议补充编译、guide 反馈、真实 HTTP 假模型、StepCard 展示及恢复测试。用户原文没有的新事实必须标为测试补充；评测不能统一灌 not_solved 驱动这些结果问答。
