# 官方 63 单残留案例归因分类

配套 `spec_2026-10-10-0840_k1-k9-root-cause-and-plan.md`。目的：区分「系统缺陷」「Agent 能力边界」「知识不支持」「官方资料问题」「评测口径」，让后续迭代只投入能改变结果的地方。

证据来源：round-08 / round-10 逐案复核、我方 retest-1853 终测、`data/official/qa.yaml`（875 条）按型号与关键词的覆盖查询、工单原文。

## 分类定义

| 类 | 定义 | 对策 |
| --- | --- | --- |
| S 系统缺陷 | 信息齐全、知识存在，流程或判定逻辑错；确定性代码可修 | 修代码，加回归 |
| A Agent 能力边界 | 判定依赖模型对自然语言的理解（适用前提、澄清措辞、多语、读图），结构化后能收敛但不能保证 100% | 收窄模型输出到封闭字段，服务端校验；接受残留，靠澄清与人工兜底 |
| K 知识不支持 | 官方 Q&A 集没有对应条目或条目残缺；正确行为是如实说明并交人工 | 不修系统；记录缺口反馈资料方 |
| O 官方资料歧义 / 考点 | 原文自相矛盾、术语可疑或刻意设计的边界条件；正确行为是保留原文、澄清或按规则办 | 不改原文；人工核对；按 SOP 处理 |
| E 评测口径 | 系统行为正确，但评测驱动停在问句或标注终点与实际合理终点不同 | 改驱动或标注，不改生产 |

## 汇总

| 类 | 单数 | 可由代码改变结果 |
| --- | --- | --- |
| S 系统缺陷 | 11（含 T41 两个问题） | 是 |
| A 能力边界 | 约 12（与 S / E 有重叠） | 部分：结构化后收敛 |
| K 知识不支持 | 5 | 否，反馈资料方 |
| O 资料歧义 / 考点 | 7 | 否，保持现状 |
| E 评测口径 | 8 | 改驱动 / 标注 |

一单可能同时落两类（T41 = S + A + E，T48 = K + S）。按「能否由我们改代码改变结果」排序投入：S → E（成本最低）→ A（阶段 B 编译）→ K / O 只记录。

## 对指标的意义

终测 sop 87% 的 8 个 ✗ 全部是 E 类；真正会给错误答复的是 S 类里的 T23、T41（第八轮）、T53 分支，共 3 单，其余 S 类是重复 / 展示 / 统计问题。K 与 O 类系统行为已经正确，不应被算成失败，也不应为它们加代码。

因此合理目标不是 100%：以 63 单计，K + O 里系统已正确的 12 单保持；S 类修完后可消除 3 个错答与 8 个重复 / 展示问题；E 类改口径后 sop 可到 95% 左右；剩余是 A 类的概率残留，用澄清与人工兜底。
