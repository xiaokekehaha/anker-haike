## 3. 难点

每条按「为什么难 → 例子 → 我们的处理 → 状态」。状态：已解决 / 部分 / 局限（资料限制，备注即可）。

### 3.1 理解层

| 难点 | 为什么难 | 例子 | 处理 | 状态 |
| --- | --- | --- | --- | --- |
| 多格式首封 | App 表单有多语种字段名，设备推送与客户自述混在一起；推送里的「contact customer service」不是客户要人工 | T11 T16 T22 | 确定性解析表单；推送字段标为 device_message，不当作客户请求 | 已解决 |
| 物理互斥 | 「没收到货」的机器不可能有故障现象，模型约 25% 读错 | T1「Only the replacement parts kit」被读成换货 | 原话含「未收到」时去掉排障 / 换货意图 | 已解决 |
| 多诉求增删 | 模型会漏诉求，也会替客户加诉求 | T9 暂缓发货被漏；T53「replacement or fix it」多出退款 | 改单、配件采购按原话补；退款必须有退款原话 | 已解决（P0） |
| 肯定句当故障 | 「the left one does work」字面肯定、语境在求助 | T50 被问右侧吸力；B10 被反转成左侧没吸力 | 只说某部分正常的现象记为不确定，固定开放追问 | 已解决（P0） |
| 已做 / 已排除事实 | 「没堵」「已擦」「水箱满」是排除信息，不是动作，词表覆盖不了；还会出现在表单字段里 | T16 T27 T31 T37 | 进指南前用客户原话核对每一步，已做过或已排除则跳过 | 已解决（P1） |
| 多语言 | 荷兰语「tank nog vol」模型可能读不出排除含义 | T37 第一轮回放 | 提示词给例子 + 说明按意思判断 | 已解决（P1），有随机性 |

## 4.1 物流

```
 物流诉求
    │
    v
 有订单号 / 运单号？ ──否──> 追问单号（T7）
    │                         └─ 客户说「手上没有」──> 说明查不了 + 去哪找，补上即查（B12）
    是
    v
 查订单与各包裹轨迹
    │
    ├─ 客户说的包裹内容与订单记录对不上 ──> 并列两份记录，请客户确认是哪一票（T2 T47）
    │
    v
 主包裹状态
    ├─ 已送达 ──────────────> 告知送达信息，不补发
    │                          客户坚称没收到 ──> 提承运商调查单（可暂不办理）→ 转人工（T1 T3 T4 T6 T10）
    ├─ 退回发件人 ──────────> 补发单（客户确认）→ 转人工（T8）
    ├─ 在途且已过预计送达日 ─> 补发单（同上）（T5）
    ├─ 在途未逾期 ──────────> 告知预计送达日，逾期再联系
    ├─ 预售未发 ────────────> 告知预计发货日（T9）
    │                          同时要求暂缓 / 取消 ──> 改单交人工；发货日只说「原计划」（4.7）
    └─ 信息不全 ────────────> 转人工核查

 禁止：已送达的包裹承诺补发；编造物流状态。
```

## 4.4 质保判断（SOP 主干）

```
 进入质保判断
    │
    v
 有订单号？
    ├─ 有 ──> 读订单的质保结束日期（不按地区推算）
    │           ├─ 已过保 ──> 告知过保日期，委婉拒绝免费换货 / 退款；
    │           │            诊断仍可继续，不再索地址换机（T29 T38 T51 T53）
    │           └─ 保内 ────> 收齐四项证据：订单 / 凭证、地址、故障照片或视频、SN
    │                          └─ 齐了 ──> 换货单卡片 → 客户确认 → 提交 → 转人工（T46 T55）
    │
    └─ 没有 ──> 首封写了购买商家 + 国家？
                  ├─ 写了 ──> 查经销商名录（国家精确 + 商家模糊）（T45）
                  └─ 没写 ──> 请提供订单号或购买凭证（凭证上看商家、国家、日期）（T49）
                               └─ 客户说「现在没有」──> 说明查不了、不会提交、去哪找（B17）
                  │
                  v
              经销商判定
                  ├─ 授权 ───> 按购买日 + 12 个月判保内 / 过保，同上
                  └─ 非授权 ─> 引导客户联系购买商家售后

 禁止：核保前承诺换机；过保后索地址；「covered by warranty」当成已确认（T14）。
```

## 4.6 转人工的几种来路

```
  ┌─────────────────────────────┬───────────────────────────────────────┐
  │ 来路                         │ 交接时带什么                          │
  ├─────────────────────────────┼───────────────────────────────────────┤
  │ 客户明确要人工（R3）          │ 原话、已做步骤                        │
  │ 安全风险（R4）               │ 风险原话；停止使用的提醒              │
  │ 资料缺失 / 未收录码（R5）     │ 区分「信息不足」与「知识缺失」        │
  │ 多次追问仍不明（R7）          │ 问过什么、客户怎么答                  │
  │ 服务单已提交（SOP 终点）      │ 服务单号、证据清单；不算托管失败      │
  │ 改单 / 改地址 / 配件采购      │ 原诉求、相关订单                      │
  └─────────────────────────────┴───────────────────────────────────────┘
  转人工后客户补充了具体现象且原因是 R5 / R7 ──> 可重新回到排障（T60）
```

## 4.7 改单 / 改地址 / 配件采购

```
 暂缓发货 / 取消订单 / 改买型号 / 改地址 / 买不到配件
    │
    v
 本系统没有对应服务单类型 ──> 如实说明自己办不了，交给能办的同事（案件进人工队列）
    │
    v
 同一句里的其他查询照常回答（T9 的物流；发货日只说「原计划，是否暂缓由同事确认」）
```

## 4.8 投诉 / 情绪

```
 辱骂 / 强烈不满 / 平台投诉威胁
    │
    v
 有故障内容？
    ├─ 有 ──> 照常排障，降低步骤负担；不把投诉当成转人工请求（T56 T60）
    └─ 没有 ─> 首封：致歉，请描述现象或选人工；不说「还没解决」（T58）
               已排障过：可暂停或选人工
```

## 4.9 信息不足

