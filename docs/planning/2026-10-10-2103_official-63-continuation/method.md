# 方法与复现

## 分层

主层是T1–T63：重新建立会话，首轮只发原工单正文和官方本地附件；系统明确索型号时按官方产品列补。操作卡统一模拟未解决；遇独立问题、材料、确认或人工边界停止。不用预期结论指导模拟客户，不猜未知事实。

补测单列：B01–B18沿用历史固定分支；R01–R05重复指定首轮；B19–B27是此次针对已知修复加入的定向分支。后者在运行前写入addendum与scenarios，不能当作盲测或混入63主层。动作都仅在本地评测服务执行，不操纵实物，不代做人工批准。

“合格”是实际观察范围内方向、事实、证据和权限合理；必要澄清和缺材料可合格，不表示最终解决。“需改进”须有当前输出/流程依据；“待核”用于事实或适用性无法确认。每案主分类唯一，并存标签可重叠。首轮与整个观察路径分别统计。定向分支没有走到预设目标时明确记录，不能按计划宣称已测试。

## 中文与独立判断

客户原文和完整系统文字、卡片标题/正文/条件/选项/媒体均保留，每轮提供中文业务译述。译述压缩重复礼貌语和字段，不增加客户事实。相同英文片段可复用旧译文；新输出人工补译。原文、模拟补充、评审判断分别标明。

逐案按原意、故障对象、已做事实、来源适用性、是否可反馈、结束状态核对。通用知识用来查逻辑，产品功能及政策用官方资料核；来源有误仍应指出，不能把有来源等同产品事实必然正确。未确认的厂商细节不以个人经验补写。

## 证据

- run/与branches/保存原始会话及前后运行指纹，逐案新session；采证失败保留。
- enrichment/只读补采同一session的快照、journey和案件，不重发消息。
- verification.json校验工作簿C2:C64与官方YAML、首轮正文逐字符一致，附件列表及哈希、事件契约、done事件、唯一会话、版本和原始记录哈希。
- review-data.yaml与branch-data.yaml保存中文译述与人工裁定；metrics.json离线重算。
- document-verification.json检查译述覆盖、英文消息与卡片原样保留、统计、链接、原始文件未改及密钥模式。
- knowledge-selected.json保存重点来源，image-check.md记录实际查看的10张原图。远程媒体URL不等于已上传附件。

## 复现

Makefile没有63案专用目标，按项目既有驱动运行，后端仍用uv加载根.env。必须选择新输出目录，不覆盖本轮证据。真实评测调用配置模型；离线生成和只读补采不调用模型。

```bash
make health
cd orchestrator
uv run --env-file ../.env python ../docs/planning/2026-10-10-2103_official-63-continuation/evaluate_long.py --output /tmp/haike-next-63 --concurrency 1
uv run --env-file ../.env python ../docs/planning/2026-10-10-2103_official-63-continuation/evaluate.py --layers BR --output /tmp/haike-next-branches
```

本轮未改业务代码、未构建镜像、未跑全量单测、未提交。只测串行；有限重复不能给出模型统计稳定率。后台采证错误、模型重试和业务错误分别记录，不能互相替代。

本轮测的是实际HTTP会话与返回的卡片字段，不是前端视觉验收。串流文字为采证会拼接，不因拼接处缺空格推断页面排版错误。自动校验确认译文条目覆盖和原始证据一致，不替代逐案人工语义判断。
