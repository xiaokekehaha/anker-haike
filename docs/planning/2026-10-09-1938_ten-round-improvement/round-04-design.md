# 第 4 轮：保留知识层级，禁止跨故障小节串行执行

## 问题与证据

第三轮 T53 选择 bp-0114 后，按无法开机的小节执行，随后又进入加热故障小节。原文有清楚的两级编号：顶层 1/2 是两个故障，带短横线的 1…5 是各故障下的检查。split_steps 把二者展平成同一数组；Plan 又把数组线性串起来。这是结构信息被丢失，不能靠减少模型随机性解决。

## 方案

在知识编译边界保留原文的顶层故障小节及其原始段落位置。对“多个故障标题各自包含嵌套编号操作”的文档，生成入口事实选择节点，选项为原文小节标题，分支分别指向该小节；小节末尾固定耗尽，不能落入下一故障。当前无法可靠自动定位小节时先询问，允许保守地多问一次，不自动猜用户选择。普通线性检查、阶段标题及人工审核分支不改变。

这一步复用现有 question/options/branches，不引入执行用模型调用，也不增加前端协议。选择节点是系统流程问题，物理操作仍只来自原文。原段落步骤 ID 不重排；入口节点使用独立 ID，段落图片和引用继续按原位置定位。

同时将明确的 Applicable Models / Applicable Error Codes / Core Symptoms 索引尾段从操作正文分离，原始 QA 文件仍保留这些信息用于来源核对。不能仅因正文某处含有这些词就删掉正常句子，必须是独立字段行。

## 开发需求与验收

| ID | 需求 | 验收 |
| --- | --- | --- |
| R6.2a | 多故障小节为互斥分支 | 合成两个不同故障的嵌套文档及 bp-0114 都先选择；任一分支 not_solved 到本分支末尾即耗尽，永不执行另一分支；普通编号指南不增选择 |
| R6.2b | 路由尊重分支游标 | 回答入口选择后，guide 不能被 decide_next 重置回第一个未答步骤而跳回错误小节；结构化反馈与多轮解释都保护所选分支 |
| R6.2c | 索引信息不变操作 | rv-0138 卡片只含更新/重启操作；独立索引行仍在官方原文件；其他句子不被删除 |
| R6.2d | 来源、人工审核与资源边界 | bp-0032 人工分支、bp-0123 审核禁用节点、精确码、媒体锚点继续通过；事实选择节点不要求设备在手 |

混合段落拆分仍需下一步设计：问句、操作、材料请求、条件关系必须一起保留，不能只按句号切开导致条件丢失。本轮不宣称解决整个知识编译问题。
