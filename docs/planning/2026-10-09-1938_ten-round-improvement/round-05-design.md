# 第 5 轮：已做操作必须覆盖整张操作卡

## 问题与追踪

第一轮 T29 checkpoint 证明：“cleaned it” 既跳过清洁步骤，又跳过包含 cleaning task 字样的密封/压盖检查。当前规则用字符串包含找动作，任意一个动作和部件相交就跳过整段；未识别部件还当通配符。这把“无法确认做过什么”错误转换成“整个检查完成”。

## 方案

保留用户已做操作去重，但采用保守的完整覆盖语义。词匹配使用边界和有限屈折形式；没有明确对象的“cleaned it/everything”不授权跳过具体部件。仅肯定、有效的用户报告参与匹配。操作卡中每个识别出的动作与所有涉及部件都必须被同一条已做报告覆盖；存在额外检查、拆卸、安装等未覆盖操作或问句/材料要求时不跳过整卡。常用同义部件可规范化（electrical connections/contact），不能用 QA 或工单编号。

这一步优先修复错误跳过，可能保留某些重复步骤。要进一步减少重复，必须把复合操作编译成有独立前置条件和结果的节点；不能为了少问而宣称客户已完成未证实操作。

## 开发需求与验收

| ID | 需求 | 验收 |
| --- | --- | --- |
| R8a | 未知对象不通配 | cleaned it/everything 不跳过明确的触点、托盘、密封步骤 |
| R8b | 动作不按子串猜测 | cleaning task、new、full 不被当成清洁、更换、补水完成证据 |
| R8c | 肯定报告及完整覆盖 | 否定/不确定事实不跳步；clean contacts 可被 cleaned electrical connections 覆盖，clean + inspect 不可只靠 clean 跳过 |
| R8d | 真实执行历史不受影响 | 卡片反馈历史仍按 instruction_src 去重；问题间历史隔离；HTTP 重复抑制有准确对象，原宽泛跳步测试改为验证不越界 |

源文档不改，模型与知识库单测保持离线；完成相关回归后全量复测 63 单。
