# 剩余问题的架构、流程与交互建议

## 判断

建议局部重构“官方资料到可执行步骤”的转换模块，以及请求到任务的结构化契约。现有业务执行、案件审批和事件流已经能承载这些改动，不建议因个别案例整体重写系统。也不应继续靠增加提示词段落、相似词规则或 QA 白名单修每个新失败。

## 1. 适用性与条件作用范围（优先）

问题：T41 第八轮明确说没运行拖地，但系统命中“烘干不够干”的 rv-0146，要求升级后再拖地。检索结果与“烘干”相关、来源可追溯，仍不足以证明操作前提成立。当前 supported_symptoms 只是模型自报的关联；长段里的条件没有独立类型。

方案：在知识编译阶段建立可审核的中间表示：目标现象、必要前提、条件分支、动作、问句、材料、说明、交接、来源区间。运行时将每个必要前提与当前事实比较为成立/不成立/未知；不成立则不能执行，未知且会改变下一步时才澄清。不能让诊断模型同时提出候选又独自证明全部前提。模型负责抽取建议，审核或确定性校验负责可执行范围。

需求：

- K1：每个节点保留原文位置和条件作用域；拆分不能丢掉 if/after/unless，也不能把说明变成动作。
- K2：必需前提有来源事实或用户回答；缺失时不默认为成立。未拖地却报错、正常结束但结果差、从未启动、启动后中止等同主题反例分别验收。
- K3：至少以两个产品类别的合成结构和留出案例验证，而非只重放 T41。对正常顺序步骤、互斥分支、混合条件、媒体要求做人工语义抽查。
- K4：把“未召回”“召回但不适用”“资料残缺”“模型/预算不可用”作为不同观测结果；不能统一显示“知识库没有”。

可选复杂度：后续可做知识编辑器、自动离线编译和版本回滚。本轮不需要为验证上述语义先开发完整编辑器。当前只实现了明确多故障标题分支和明显悬空引用，不能称已经完成通用编译器。

## 2. 复合操作与已做事实

问题：T27/T31/T37 等包含用户已清洁、已加水的内容，复合卡还会重复部分动作。直接整卡跳过会重现 T29 丢掉未做密封检查的问题。

方案：依赖 K1 把动作拆到可核对的粒度；已做事实分别绑定对象、动作、结果和时间条件。完全覆盖的动作跳过，未做部分保留；条件变化时允许重新检查并说明原因。当前采用保守整卡覆盖，宁可记录局部重复，也不虚构用户已完成其余动作。

需求 K5：部分完成、多对象、否定事实、维修后条件变化、不同设备同类部件分别验收；操作计数只计实际收到的操作反馈。

## 3. 请求目标与任务恢复

第九轮修复“额外查询没有结果字段仍输出默认订单信息”、字段在任务推进时丢失，以及请求与症状引文被强制嵌套。剩余语义误读不能靠引文包含关系完全消除。

需求 K6：逐步把任务统一为“目标结果＋业务对象＋来源＋完成条件”，明确并列、替代、条件性请求的关系。内部工具读取不是用户任务。来源证明原话存在，语义评测仍需证明它确实要求该结果。不要在现有请求引文旁再叠加多套互相矛盾的意图状态。

## 4. 业务流程与比赛边界

不改官方质保/物流规则，不以测试方便为由自动同意退款换货。提交人工审核和真人接单不同，办理完成与设备修好也不同。比赛评测到真实 awaiting_approval 即停止；可核对同次答复是否已包含允许的只读查询，不模拟审批后操作。产品实际使用时可继续接收补充信息，这是比赛边界之外的能力。

## 5. 交互与来源

T50 应澄清实际故障，不能把 does work 擅自改为不工作；T53 已说无法开机时，不应反复问无法开机还是吸力弱。T48 当前证据不足时如实回答是正确边界，但原始引用 ID 应渲染为文档标题和可打开的位置。长段操作、问句和上传要求要分别呈现，并让用户清楚本次需要做什么。

需求 K7：以信息增量评估追问必要性；已有事实可回答的问题不重复问。来源卡显示文档名/条目/原文定位，证据不足提示必须限定“当前资料/召回证据”，不扩张成“所有官方资料没有答案”。第十轮 T35 还输出了不在本轮证据集合的拼接 UUID；引用必须由有效证据映射生成，不能直接信任模型正文中的引用字符串。T40/T32 链接实际在 media，验收必须包含媒体字段。

## 6. 风险结论也需要语义证据

第十轮 T23 只有 E41 Battery abnormal，仍触发 R4。checkpoint 风险状态为 reported；输入预检记录仅 R3，模型风险入口位于 conversation/reduce.py，接受 reported 标签和存在的原文引文即成立。引文真实只能证明客户说过，不能证明他说的是物理安全事件。官方 rv-0138 提供更新/重启，不能把普通报错直接当成已发生冒烟或鼓包。

需求 K8：安全主张保存具体危险现象、原文范围、肯定/否定/假设语气、对象和来源。主张必须被引文语义支持；普通故障、设备显示文字、知识文档警告与用户实际危险报告分开。缺少证据的高后果判断应澄清并保留必要限制，不为具体错误码设置豁免，也不移除当前安全能力。验收覆盖真实冒烟/鼓包、普通电池报码、否定、转述手册、历史危险与更正，不能只测 T23。涉及风险策略的取舍需要单独评审，本轮不通过降低保护来换成功率。

## 7. 咨询、业务案件和整体问题的终点

第十轮只读 SQL 与 checkpoint 交叉核验发现：T35 产品咨询 task.status=answered，却 consult_answered=false、stage=intake，显示 in_progress。product_questions.answer_product_question 只写自己的完成状态，analytics.classify 未读取它。T53 换货案件 closed_unresolved，但维修任务仍 active，现有 classify/episode/METRIC_ROWS_SQL 优先案件状态，因此整个 issue 被判终结。第八轮修掉“未解决＝真人参与”是必要修复，却没有完成多诉求聚合。

需求 K9：分别记录每个请求完成、业务案件结案、整个问题完成；问题仍有 active/pending 用户请求时，案件结案不能直接关闭整个问题。所有答复入口通过统一的任务完成契约记录“已回答/资料不足/未回答”，流式输出完成不等于内容已回答。聚合定义一次，共用于 checkpoint 派生、episode 和看板 SQL；既覆盖 T35/T53，也覆盖无案件咨询、查询后继续排障、多个案件、人工等待和历史终点。不得简单交换 if 顺序或把产品回复全标成功来掩盖新旧冲突。

## 官方资料待核

rv-0371 缺引用、T13 当前 QA 集缺 5116 是确定的资料覆盖问题；T50 原话、bp-0111 speaker cover、T48 绿灯含义仍需核对。没有证据证明是主办方特意留坑。详见 official-source-review.md。
