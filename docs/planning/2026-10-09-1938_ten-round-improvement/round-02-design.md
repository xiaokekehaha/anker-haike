# 第 2 轮：知识入口和说明终点

## 问题与根因

T28 的重启后硬件结论、T35 的正常回充说明、T40 的无具体步骤说明被当成操作。原始 QA 确实包含这些文字；不是知识库没命中，而是单段 answer 和 FIRST_TRY 直接构造默认 action。T51 的原因标题也没有可执行动作。另一处缺陷是 guide 跳过 statement 后若没有下一张卡，累计的说明会丢失。

## 方案

1. 所有入口都调用相同的类型构造器；Guide 保留所有节点，Plan 只消费这些节点，不再次构造默认 action。保留现有原段落编号、媒体和人工分支，避免本轮同时改变定位。
2. 先修可确定的语言边界：原因标题、描述设备行为、被动说明不因为包含 charge / use / restart 等动词就变成指令；明确请求执行的句子仍是 action。售后条件结论没有客户操作时归为 handoff。未解决全部混合段落，本轮不宣称 R6 全部完成。
3. prepare_step 返回尚未展示的说明。纯说明计划产生 explained 终点；有真实操作失败后的尾部说明照常展示，并继续现有耗尽策略。说明既不要求 solved，也不增加执行计数。
4. graph 以普通消息展示说明，保存可追溯证据。纯说明完成当前答复并推进真实待办；不调用故障解决的 closing_text，不写 solved。后续解释及统计区分 answered 和 resolved。
