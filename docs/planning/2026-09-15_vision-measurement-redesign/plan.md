## 0. 为什么要从第一性原理重来一遍

票 62 的结构件已经全部落地：`FaultLocalization` 契约、`vision_vocab.yaml` 受控词表、`signature → plan_id` 映射、`prepare_retake` / `vision_conflict` 两个节点、前端 `RetakeCard.tsx`。**骨架是完整的，但里面流的数据没有任何可信度保障。**

调研给了一堆「业内怎么做」的答案。但照抄清单会漏掉一件事：这些做法背后是同一个判断——**照片不是内容，是一次测量**。把这句话当公理推下去，能自己推出该做什么、该砍什么、以及先做哪个。下面就这么推。

---

## 1. 六条公理

### A1. 照片的价值是它消除的决策不确定性，不是它包含的信息量

用户拍照的唯一目的，是让系统在**不追问他**的前提下把某个未知量定下来。所以正确的问题不是「这张图里有什么」，而是「下一步决策卡在哪个未知量上，这张图能不能定它」。

**推论**：抽取字段表必须从下游决策**反推**，不能从「图里能看出什么」正推。没有消费者的字段不该存在——它不产生价值，却要付出 token 成本，并且每多一个字段就多一个幻觉入口。

### A2. 误测的代价比漏测高一个数量级，因为误测是静默的

| | 可被系统察觉 | 补救成本 |
| --- | --- | --- |
| 漏测（没读到型号） | 是，字段为空 | 追问一句 |
| 误测（编出型号 X10 Pro） | **否，字段看起来完全正常** | 错误消歧 → 整条排障路径错 → 会话失败 |

实测证据（[research.md §13.1](../2026-09-14_vision-image-understanding-research/research.md)）：铭牌占全图 0.15% 时，`deepseek-flash` 编出格式完全合理的假铭牌，两次复跑编出的内容还不一样，且一个问号占位都不用——而提示词里明确要求了。

**推论**：系统必须结构性地偏向「宁可不知道，不可知道错」。这要求每个字段有显式的「未知」态，并且**未知是默认值**，不是例外分支。

### A3. 模型无法自知其无知

低光下识别准确率 0.99→0.22，而模型自报置信度恒在 0.87–0.90，错误检测 AUROC≈0.50。模型看不见的时候，它不知道自己看不见。

**推论**：可信度信号**必须外生**。三个可用的外部来源：

- **像素层**：清晰度、亮度、尺寸。可计算，确定性，零成本。
- **一致性层**：同一事实在两次独立测量下是否一致（如裁剪前 vs 裁剪后）。
- **交叉层**：图像结论 vs 用户文字 vs 知识库。

我们现在 100% 依赖模型自评：`image_quality.usable` 是模型说的，`confidence` 也是模型说的，而 [localization.py](../../../orchestrator/app/diagnose/localization.py) 的 `signature_plans` 还拿 `confidence >= 0.7` 当阈值去决定要不要提高 plan 先验。这是设计层面的缺陷，不是调参能修的。

### A4. 信息的物理上限在像素里，不在模型里

实测：同一张图，`deepseek-flash` 全图 0/3，九宫格裁剪 + 2× 放大后 3/3。信息一直都在，只是没送到模型眼前。

**推论**：结果不足时，第一反应应该是**重新测量**（裁剪放大、让用户补拍），而不是**加强推理**（换更大的模型、加思维链）。前者成本是一次小图调用，后者成本是全链路升级，而且在信息根本不在像素里的时候，再强的模型也拿不到。

### A5. 先验会污染测量，被污染的测量无法自证

实测：图中是滚刷缠绕、滤网干净，用户说「应该是滤网堵了」，`glm-4.6v` 两次都**丢掉了真实的滚刷缠绕**，只回一句「滤网正常」。

这里的关键不是模型被骗了多少，而是：**一旦把先验混进测量，测量就不再独立，后续任何交叉验证都失效**——因为两个信号已经相关了。我们现在让同一次调用既看用户文字、又输出 `conflicts_with_text`，逻辑上是自指的：被污染的一方在报告自己有没有被污染。

**推论**：视觉调用不能看见用户文字。冲突判定必须在两个**独立**结论之间做。

### A6. 看图是一个可重入的循环，不是一个节点

补拍、裁剪复看、回显确认，本质上都是「再测一次」。既然是循环，就需要**退出判据**。

**推论**：退出判据应该是「驱动决策的字段是否都已确定」，而不是「模型说 `usable=true`」。前者由我们定义，后者由模型说了算——回到 A3 的问题。

## 2. 用公理照现状

| 公理 | 当前实现 | 代码位置 | 违反程度 |
| --- | --- | --- | --- |
| A1 字段由决策反推 | `severity` / `location` / `quote_region` **全仓零消费者**，只出现在要求模型生成它们的提示词字符串里 | [vision.py:69](../../../orchestrator/app/diagnose/vision.py) | 三个字段纯浪费 + 三个幻觉入口 |
| A2 未知为默认 | 词表只有「其他」，没有「不可辨」。「是个没见过的部件」和「根本看不出来」被归进同一个桶 | [vision_vocab.yaml](../../../config/vision_vocab.yaml) | 无法表达未知 |
| A3 可信度外生 | `usable` 与 `confidence` 全由模型自评；无任何像素层门控；无一致性检验 | vision.py、localization.py `signature_plans` | 完全违反 |
| A4 重新测量优先 | 无裁剪复看；一次调用定生死。主位 `deepseek` 每图 384 token | [models.yaml:63](../../../config/models.yaml) | 完全缺失 |
| A5 测量与解释分离 | 用户文字与图片在**同一次调用**，且文字在图片**之前**；`conflicts_with_text` 由这次被污染的调用自己产出 | [vision.py:103-115](../../../orchestrator/app/diagnose/vision.py) | 完全违反 |
| A6 显式退出判据 | 退出判据是模型自报的 `usable` | [graph.py:502-505](../../../orchestrator/app/sessions/graph.py) | 判据来源错误 |

另外两项基础设施缺口：

- **无任何图片预处理**：`orchestrator/app/images/` 里没有 EXIF 转正、没有缩放，原始 bytes 直接 base64。手机竖拍是售后场景的绝对主流，而所有厂商都把 rotated 图列为已知失效条件。
- **评测集是空占位**：`data/eval/vision/cases.yaml` 内容是 `cases: []`，注释写着「人工确定性规则回归样本，不代表真实模型评测」。仓库内、本地都**没有任何真实故障照片**，`data/bakeoff-images/` 被 gitignore 且不存在。

## 3. 由公理推出的目标形态

### 3.1 字段表（A1 反推）

从下游三个真实消费者反推，只保留四组字段：

| 字段 | 驱动哪个决策 | 现有消费者 |
| --- | --- | --- |
| `findings[].{part, phenomenon}` | `signature → plan_id`，提高排障计划先验 | `signature_plans()` |
| `findings[].{evidence, cell}` | `evidence` 是反幻觉锚点；`cell` 是裁剪复看的坐标 | 新增（`cell` 让原 `quote_region` 第一次有了消费者） |
| `model_hint.{raw, readable}` | 产品消歧，省一轮追问 | [graph.py:392](../../../orchestrator/app/sessions/graph.py) |
| `safety_terms[]` | CP-in R4 安全升级 | graph 的 `vision_risk` |
| `image_quality.{usable, reasons}` | 补拍路由（但 `usable` 由外部门控覆盖，见 3.2） | [graph.py:504](../../../orchestrator/app/sessions/graph.py) |

**砍掉**：`severity`、`location`、`confidence`。前两个零消费者；`confidence` 是模型自评，A3 已判定无效。
**移走**：`conflicts_with_text` 从模型输出移到代码层计算（A5）。

砍字段不只是省 token。每个字段都是一次「请你给我一个值」的要求，而模型面对要求时倾向于给出值而不是拒绝——这正是 A2 的幻觉来源。

### 3.2 可信度的三个外部来源（A3）

```
像素层（确定性，零模型成本，先于任何调用）
  Laplacian 方差 → 失焦        亮度直方图 P50/P95 → 过暗/过曝
  短边像素 → 太小/太远          命中硬阈值 → 直接补拍，不调模型
一致性层（A4 的副产品）
  裁剪复看的结论 vs 全图结论不一致 → 该字段降为未知
交叉层（A5 的产物）
  图像结论 vs 用户文字（代码层符号比对）→ conflicts
```

`image_quality.usable` 的最终值 = 像素层判定 AND 模型判定。模型只能把「我也觉得不行」加进来，不能把「我觉得行」凌驾于像素层之上。

### 3.3 测量循环（A6）

```
上传 → [L0 预处理: EXIF 转正 + 缩放] → [L1 像素门控]
                                          ├ 不合格 → RetakeCard（带具体指引）→ 等补拍 ↺
                                          └ 合格 ↓
                              [L2 纯图抽取（不含用户文字）]
                                          ↓
                              退出判据: 决策字段是否都已定？
                                ├ model_hint 未定且需要消歧 → [L3 裁剪复看] ↺
                                ├ findings 空且图可用 → 按无图继续（诚实降级）
                                └ 已定 ↓
                              [L4 代码层融合: 冲突检测 + signature → plan + 安全词]
                                          ↓
                              [L5 回显确认 / 冲突澄清 / 安全升级]
```

和调研里的五层流水线是同一个东西，但这里的每一层都能追溯到一条公理，而不是「业内都这么做」。

## 4. 排序原则：按静默错误代价，不按工作量

A2 说误测代价远高于漏测，那么修复顺序也应该按「该缺陷会造成多严重的静默错误」排：

| 序 | 缺陷 | 静默后果 | 对应公理 |
| --- | --- | --- | --- |
| 1 | 小铭牌上编造型号 | 错误单命中 → 整条排障路径错，用户全程不知道 | A2 + A4 |
| 2 | 用户先入之见挤掉真实故障 | `findings` 为空 → 降级纯文字，无任何错误信号 | A5 |
| 3 | 差图静默通过 | 后续所有结论建立在看不清的图上 | A3 |
| 4 | 自评 confidence 当阈值 | plan 先验被随机数驱动 | A3 |
| 5 | 无用字段 | 成本 + 幻觉面，但不直接致错 | A1 |
| 6 | 改动无法验证 | 上面五项修完也不知道有没有修好 | 贯穿 |

注意第 6 项：它排在最后，但**必须最先开工**，因为它是其余五项的验收前提。这不矛盾——它的优先级低（不直接致错），但它的**依赖位置**在最前。

## 5. 分阶段计划

12 天，五个阶段。每个阶段的完成标准是「某条公理不再被违反」，不是「某个函数写完了」。

### 阶段 0（9/15，半天）：建立可验证性

没有这一步，后面四步都是在盲改。

- 把 [research.md 的两个实测脚本](../2026-09-14_vision-image-understanding-research/probes/) 固化成回归用例：**小字铭牌**（验 A4/A2）、**误导文字**（验 A5）。合成图对这两类问题已被证明有判别力。
- `data/eval/vision/cases.yaml` 从空占位改成真正的 schema，先填这两个合成用例 + 现有 4 条 signature 的正例。
- `score_vision` 从关键词召回改成字段级：part 准确率、phenomenon 准确率、plan 命中率、**幻觉率**（正常件上报出非「正常」现象的比例）、**安全召回**。

**验收**：`make bakeoff` 能跑出上述五个指标，且小字铭牌用例在当前主位 `deepseek` 上复现 0/3。基线数字记录下来。

**诚实边界**：合成图验证不了真实故障纹理的识别率。这一层缺口靠阶段 4 的真实照片补，补不上就在材料里标注清楚。

### 阶段 1（9/16–9/18）：让测量不撒谎（A2 + A4，修缺陷 1、4、5）

- **L0 预处理**：`ImageOps.exif_transpose` + 按目标模型上限缩放 + JPEG q90 重编码。约 30 行，放在 `images/` 下，`observe_images` 取图后调用。顺带解决 Bedrock 单图 5MB 限制。
- **词表加「不可辨」**：`vision_vocab.yaml` 的 `parts` / `phenomena` 各加一项，与「其他」语义分离；`localization.normalize` 区分两者。
- **砍字段**：`severity` / `location` / `confidence` 从契约与提示词移除；`quote_region` 改名 `cell`（九宫格枚举），成为裁剪坐标。
- **`signature_plans` 去掉 confidence 阈值**：改为符号条件——`part` 与 `phenomenon` 均非「不可辨」且 `evidence` 非空。
- **L3 裁剪复看**：按 `cell` 从**原图**裁出该格外扩 50%，放大 2×，第二次调用只问铭牌逐字符转写。触发条件 `model_hint.readable != full`。实测证明这一步能把三家模型在全部铭牌条件下拉回满分。
- **链序主位改 `qwen-vl`**：一行配置。依据是 deepseek 在小铭牌上**静默编造**，不是准确率差几个点。

**验收**：小字铭牌用例从 0/3 到 3/3；幻觉率指标上，假铭牌不再出现；预处理后竖拍图不再旋转送入。

### 阶段 2（9/18–9/20）：让测量不被污染（A5，修缺陷 2）

- **`build_messages` 图文分路**：视觉调用只收图片 + 指令，**不含用户文字**；顺序改为图先文后；多图各自前置 `Image N:` 标签。
- **提示词重写**（版本升 `2026-09-15.1`）：describe-first 两段式（先写 ≤5 条可见事实，再填受控枚举）；全部改正向指令（「仅输出图中可直接看到的内容」而非「不要编造」）；每条 finding 必须挂一条 evidence；铭牌逐字符转写、看不清的字符写 `?`。
- **冲突检测移到代码层**：`conflicts_with_text` 不再由模型产出。新增 L4 融合函数，把 `findings` 与 `interpret` 已抽出的 `facts / symptoms` 做词表级比对，命中「同部件不同现象」或「用户点名部件 A 而图中只在 B 有现象」才算冲突。零模型成本、可单测、可解释。

**验收**：误导文字用例上，三家模型都不再丢失真实故障；`vision_conflict` 路由由代码层判定驱动，且有单元测试覆盖三种冲突形态。

### 阶段 3（9/20–9/22）：让可信度外生（A3，修缺陷 3）

- **L1 像素门控**：新增质量检测模块，四项指标 + 阈值配置进 `vision_vocab.yaml`。命中硬阈值直接走 `prepare_retake`，**不调用任何模型**。
- **阈值标定**：用合成图做退化扫描（逐级降亮度 / 加模糊）定出初始阈值，标注为「待真实照片复标定」。给硬软两档：硬阈值直接拦截，软阈值只在模型也说不可用时才触发。
- **`usable` 改为 AND 逻辑**：像素层与模型判定取交集，模型不能否决像素层。

**验收**：过暗 / 模糊的合成图在**零模型调用**的情况下触发 RetakeCard；`usable` 判定准确率进入指标体系。

### 阶段 4（9/22–9/25）：闭环、真实数据与材料

- **回显确认**：把「我看到滚刷缠了头发」作为隐式确认进 StepCard 首句（Google 会话设计准则：高置信低后果用隐式确认，不可逆动作才用显式确认）。
- **真实照片**：这是全局最大的不确定项，见 §6。拿到多少补多少，评测集按 [research.md §9.1](../2026-09-14_vision-image-understanding-research/research.md) 的配比扩充，重跑链序裁决。
- **预赛材料**：把本文的公理链 + 实测数据写进技术难点章节。**「看图」这一节的说服力不在于我们用了什么模型，而在于我们能说清楚「模型会静默编造，所以我们把可信度做在模型外面」**，并且有自己跑出来的数据支撑。

### 阶段 5（9/25–9/27）：demo 脚本与回归

现场 demo 建议固定四个动作，正好覆盖五难点里的四个：

1. 上传一张暗图 → 零模型调用直接出补拍卡（看图 + 接稳）
2. 补拍清晰图 → 结构化定位回显「我看到滚刷缠绕」（看图）
3. 用户说「我觉得是滤网问题」而图显示滚刷 → 主动澄清（问清 + 幻觉）
4. 上传鼓包/烧焦图 → 直接安全升级（接稳）

## 6. 阻塞点与需要你决定的

### 阻塞：没有任何真实故障照片

仓库内、本地都没有。这直接卡住「真实故障纹理识别率」这一层的验证，也卡住链序的最终裁决。三个可能来源，需要你判断哪个可行：

1. **主办方的脱敏工单里是否带图？** 目前 `kb_tickets/tickets.csv` 里没看到图片引用。如果主办方能提供，这是最优解。
2. **自拍**：家里有扫地机就能拍滚刷缠绕、滤网积灰、尘盒满——这三个正好是现有 4 条 signature 里的 3 条，成本是半小时。
3. **公开图**：电商评价区、维修论坛。版权与脱敏需要注意，只用于内部评测不分发。

我的建议是 2 + 3 并行，不等主办方。**20 张真实照片带来的验证价值，高于阶段 1–3 任何一项的代码改动。**

### 需要决策

1. **链序主位现在就改 `qwen-vl`，还是等真实照片评测？** 我建议现在就改。依据不是准确率差几个点，而是 deepseek 的失效方式是静默编造，这是 A2 定义的最高代价错误类型。改回来的成本也只有一行配置。
2. **砍掉 `severity` / `location` 要动 `haike_contracts` 契约与 JSON schema**，会影响契约测试与前端类型。确认是否接受这次破坏性改动，还是先保留字段但从提示词里移除（保守方案，仍能拿到大部分收益）。
3. **阶段 3 的像素门控阈值用合成图标定**，真实照片到位后需要复标定一次。接受这个两段式，还是等真实照片一次做完？后者更准但会让阶段 3 卡住。
4. **12 天排期是否现实**取决于投入人力，本文按单人全职估。若人力更紧，按 §4 的顺序砍尾巴——阶段 1 和 2 是「看图」这一项能否算做到的分水岭，阶段 3 之后都是加分项。

## 7. 这套规划不做什么

- **不训练任何模型**，不引入检测器 / 分割模型。赛期 12 天，且 A4 说明重新测量的收益高于加强模型。
- **不做参考图对比**。MMAD 基准显示多数模型不会利用正常样品参考图，反而掉分。要做必须先实测，不在这 12 天内。
- **不做翻拍 / AI 生图检测**。排障场景欺诈动机弱，写进材料体现纵深即可（走向理赔换货时才是真需求）。
- **不追求字段丰富**。A1 决定了字段表只会变短不会变长。每加一个字段都要先回答「谁读它」。
