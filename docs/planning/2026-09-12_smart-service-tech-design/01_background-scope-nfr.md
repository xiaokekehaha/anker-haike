# 第一步：背景与目标、需求范围、非功能需求

## 1. 背景

Anker 首届黑客松「智能服务」赛道要求实现一个面向真实售后场景的 AI 智能客服 Agent 与高交互前端，主题「真正听懂，真正解决」。作品需结合用户文本、故障图片、技术知识库和历史工单，完成从描述问题到解决或升级的完整服务流程。官方点名的难点：产品名称歧义、购买凭证渠道不一、故障描述含糊、用户带明显情绪。

现状痛点（面向方案叙述，非官方数据）：
- 售后首轮沟通大量时间耗在「确认是哪个产品」和「让用户描述清楚」上。
- 排障知识分散在说明书、FAQ、工单备注中，客服凭经验检索，新人上手慢。
- 转人工时上下文丢失，用户要重复描述。

## 2. 目标

| 编号 | 目标 | 可验证口径 |
| --- | --- | --- |
| G1 | 听懂：在歧义与情绪场景下正确识别产品并给出安抚 | 演示案例 2 中，1 次追问内锁定产品；情绪标签与语气策略在日志中可见 |
| G2 | 解决：给出可执行的分步排障并根据反馈推进 | 演示案例 1 中，用户描述后 3 轮对话内出现第一条排障步骤，最终标记「已解决」 |
| G3 | 升级：未解决时生成结构化转人工摘要 | 演示案例 3 中，摘要包含产品、故障、已执行步骤与结果、升级原因五要素 |
| G4 | 可感知：处理阶段与依据对用户和评委可见 | 前端进度条实时反映状态机阶段；每条结论可展开检索来源 |

## 3. 需求范围

### 3.1 场景与产品范围
- 主线：扫地机器人吸力异常（含吸力弱、完全不吸、间歇不吸）。
- 第二难点：产品消歧，模拟目录中「S1 Pro」同时对应吸奶器与扫地机器人。
- 升级路径：用户可上传购买凭证照片，视觉模型抽取订单号 / 渠道 / 日期，用户确认字段后规则核对订单归属产品与渠道，输出已核实事实与下一步；**不输出质保资格结论**，不做完整质保流程。
- 范围外产品：目录中的吸奶器等仅用于消歧演示，选中后进入范围外处理并升级，不排障。

### 3.3 验收用例（即三个演示案例）
- A1 排障成功：用户「扫地机不吸了」+ 滚刷照片 → 识别毛发缠绕 → 两步排障 → 已解决。
- A2 产品歧义：用户「S1 Pro 不吸了」，情绪焦急 → 安抚 + 确认卡片 → 选扫地机 → 进入 A1 流程。
- A3 升级：排障步数达上限仍未解决 → 提示上传购买凭证 → 识别订单号 / 渠道 → 用户修改一个低置信字段并确认 → 订单表未命中、经销商名录命中 → 摘要带 receipt.status=channel_in_directory 与下一步 → 进入升级。

理解与检索补充验收：A1 中「还是不吸」能承接已确认产品与未解决症状；「不是吸力小，是有异响」不再以吸力不足为有效事实；型号未知时不检索 SKU 专属知识；抽取失败、无命中、检索不可用均有既定回退。详细契约见 [03 §1.4.1](03_detailed-design.md#141-理解查询与召回的最小契约)，开发落在票 32、37。

可选增强与路由验收：开关默认关闭时没有 query.rewrite 调用；开启后「它跑完了，地上还是一堆渣」在首轮真实无命中时最多改写一次，第二轮 scope 与首轮一致。空范围、部分库故障、非法改写、预算不足、重复恢复均不得增加无效补救；第二轮仍无结果须有明确出口。路由至少覆盖模糊输入、产品歧义、用户纠正、过期按钮、人工请求，并检查第二次澄清答复仍不明时升级。见 03 §1.4.2、09 §1.1 / §4.1；票 24、32、33、37、45 与票 23 联动。

故障与边界场景（巡检脚本覆盖，非演示主线）：重复提交同一动作；连续三次「无法操作」；首句 / 中途文本 / 图片观察出现安全词；上传另一台设备的订单凭证；OCR 低置信订单号恰好命中他人订单；反馈已提交后断网刷新；服务重启后恢复；WeKnora 断开；全部模型不可用；回放包版本不符。

### 3.4 数据范围（全部模拟）
- 产品目录：约 20 个 SKU，含同名异类产品。
- 知识库：扫地机说明书 PDF 2 份、FAQ 约 50 条、排障手册 1 份。
- 历史工单：约 200 条，含故障描述、处理步骤、结果。
- 经销商名录：约 10 条。

## 4. 非功能需求

Agent 约束卡（任务类型、上下文预算、调用量、等待上限、必选工具、失败处理）见 07_agent-system-design-checklist.md §1。

| 类别 | 指标 | 说明 |
| --- | --- | --- |
| 延迟（正常口径） | 首个可见文本 ≤ 2 s；步骤卡就绪：文本轮 ≤ 8 s、含图轮 ≤ 15 s | 分别测 first_visible_ms、card_ready_ms |
| 延迟（故障上限） | run deadline：文本 25 s、含图 40 s、凭证 30 s；ModelRouter 为唯一重试层 | 08 §8 |
| 可用性 | 模型链降级（跨厂商）；检索不可用或无命中时按预写计划或升级，不用模型常识补假设 | 04 §1 |
| 可复现 | A1–A3 可在回放模式下按录制包稳定跑通；回放绑定版本清单 | 09 §6 |
| 正确性 | 未确认品类不排障；检索限定适用产品；订单命中须核对 SKU；安全词任何时刻立即升级 | 09 |
| 恢复 | 动作幂等、卡片稳定、刷新 / 断流 / 重启后视图可恢复 | 08 |
| 可解释 | 每次状态迁移与升级判定有规则编号与依据记录 | 支撑评审问答 |
| 安全 | 用户图片仅存会话期，演示后清理；API key 不进前端 | |
| 并发 | 5 个并发会话不降级 | 评委同时体验 |
| 部署 | 单机 Docker Compose 30 分钟内可从零拉起（目标，冻结前实测） | 04 §5 |
| 可观测 | 每轮记录延迟、token、状态、工具调用、检索命中 | Langfuse + 结构化日志 |
