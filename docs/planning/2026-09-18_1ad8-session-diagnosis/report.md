# 会话1ad8排查与修复

## 问题

用户先说“电池掉电很快”，按追问补充“Anker 737 充电宝型号 A1289”后，系统回复理解失败，产品仍为unknown。

## 根因

1. intake默认通道输出上限仅512 token，qwen-flash达到该上限后触发 `LengthFinishReasonError`，无法返回结构化解释，耗时5687ms。
2. interpret_turn给整条模型链的总时限只有8000ms，备用deepseek仅执行2268ms就超时，第三家未执行。
3. 完整句式的型号补充依赖模型解释。模型链失败后降级规则未识别该句，生成unknown解释，后续产品匹配没有执行。

输入估算6409 token，低于16000额度，历史未遗漏；该轮未进入检索。产品目录本身可以唯一确认ANKER-A1289。

原始调用摘要见 [model-call-evidence.json](model-call-evidence.json)。页面completed只表示降级回复正常送达，模型调用事实仍记录error。

## 修改

- `config/models.yaml`：默认通道intake输出上限512→1536，版本2026-09-18.2；保留模型顺序。
- `orchestrator/app/conversation/interpret.py`：整链预算8000→15000ms。
- 新增HTTP回归：历史512上限的失败对照、当前额度确认产品、主模型5.687秒失败后备用模型3秒成功。最后一种场景验证备用获得9.313秒时限。

## 验证

- 修改前：新增回归1通过、2失败；修改后3通过。
- 7个相关测试文件共91通过，耗时5.42秒。
- `make lint` 与 `git diff --check` 通过。
- 全部使用FakeChatModel与测试会话；没有真实模型/知识库调用，没有修改原始会话数据，没有提交Git。

## 限制

原失败响应正文未保存；输出回归模拟已记录的截断事件，成功输出为结构化替身，不能据此宣称真实模型准确率或1536额度已通过线上评测。15秒仍是整链共享上限；首位耗尽15秒时仍没有备用时间。

本轮没有构建或发布容器。Python源码位于镜像内，需重建后本地8000端口服务才能使用15秒预算，单独重启不能加载此源码修改。
