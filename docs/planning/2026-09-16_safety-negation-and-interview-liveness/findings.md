# 发现

## 1. R4 误升级：否定语义被当成风险事实（已修）

`data/demo-photos/1_滚刷缠绕_正常曝光.png` 三次复现一次：视觉模型写出观察项
「未见冒烟烧焦鼓包漏液火花」，`config/rules/safety_terms.yaml` 的 `observation_terms`
按子串命中「烧焦」，会话直接判安全风险、终止排障、转人工。

两个放大因素：

- `app/diagnose/vision.py:102` 的提示词要求「出现冒烟 / 烧焦 / 电池鼓包 / 漏液 / 火花时，
  中文与英文关键词各写一次」，诱导模型写出这类否定清单；
- 同一文件的注释又明确写着「只说要做什么，不说不要做什么（负面指令在 VLM 上接近随机地被忽略）」，
  所以**靠加一句「不要写否定清单」修不掉**，只能在匹配层解决。

用户文本路径有同一个洞：「没有焦味」「机器不冒烟」同样会命中 R4。

## 2. 问诊会无限重复同一个问题（已修）

`decide_symptoms` 的停止条件是「连续两次无进展」或「累计八次响应」，两者都只数
`response_attempts`。而 `accept_answer` 里任何新症状事实都会把无进展窗口清零
（`progress_start`），补充类输入（`primary_intent=supplement`）又根本不记账。

结果：用户每补一句话，窗口清零、计数不动，同一个判别问题可以问到天荒地老。离线探针
连发 8 轮补充，`attempts` 始终是 1、`consecutive_no_progress` 始终是 0，问题一字不变地重复 8 次。

## 3. 词表缺口让文字路径走不到已有方案（已修）

`config/symptom_taxonomy.yaml` 的「吸力下降」只收了「吸不干净 / 扫不干净」这类说法。
用户说「滚刷上缠了很多头发」「地面有残留」归不进任何故障族 —— 但同一件事图片路径早就能定位：
`vision_vocab.yaml` 的 signatures 写着 `滚刷 + 缠绕 → rv_suction_hair_wrap`，
而该 plan 的 `symptom_codes` 就是 `suction_low`。同一条已审核知识，文字路径拿不到。

## 4. 没有待办卡时仍让用户「确认具体选择」（已修）

`app/conversation/commands.py:14` 在 `primary_intent ∈ {step_feedback, answer_pending}`
且模型没给出结构化答案时，**不看有没有待办卡**就回一句
「请确认具体选择，或说明操作后是已解决、仍有问题还是无法操作。」
此时既没有可选择的卡片也没有可反馈的步骤，这句话对用户没有任何意义，
而且它会抢在排障路径前面，把该重问的判别问题吃掉。

## 5. intake 偶发不解析判别答案（未修，需按票 42 评估）

「是清扫或拖地的效果不好吗？」→ 用户答「效果不好」，qwen3.7-flash 有时返回
`primary_intent=answer_pending` 却不填 `symptom_answer`。9/16 实测六次里出现三次。

服务端已经能容错（记一次 unparsed、重问），但用户得把同一句话再说一遍。
彻底解决要么改 intake 提示词、要么在服务端按问题类型做确定性兜底解析
（yes/no 词表、symptom_selection 选项匹配）。前者要跑 bake-off，后者要想清楚
「引用原话才算答案」这条纪律要不要为判别问题开口子 —— 两条都超出本次范围。

## 6. 产品澄清也会一字不差地复读（已修，同一处改动覆盖）

`decide()` 与 `_clarify()` 重建 `clarification` 时把上一次问出去的原话丢了，
呈现层无从判断「这是第几次问同一句」。实测「请告诉我设备的品类……」连续三轮逐字重复。
