# T20/T43根因复核

本轮仅诊断，没有改应用，也没有新增真实模型调用。使用上轮完整日志恢复真实模型输入/输出，并用现有规则和pack_hits做离线差分；证据见causes-evidence.json。

## 1. T20首测：非安全词中断否定范围

观察原文“未见明显破损或烧焦”来自图像描述。规则服务只支持“否定词 + 连接词 + 安全词串”；“破损”不在安全词表，也不是连接词，因此否定解析到这里就停止。后面的“烧焦”作为未遮蔽关键词被R4命中。

最小差分：`未见明显烧焦`不升级，加入`破损或`后立即升级；无须模型参与即可复现。临时探针执行明确失败：`AssertionError: 复现T20：否定观察错误升级`。

这是已有否定语法覆盖不全，并非完全没有否定处理。更深的接口问题是安全判定依赖自由文本中的关键词，再用有限语法还原“有没有发生”，肯定/否定信息容易在此丢失。更可靠方向是让安全观察明确携带现象、肯定/否定/不确定及证据，规则按肯定事实判定；不能用遇到“未见”就忽略整句的粗放方式，以免漏掉“未见冒烟，滚刷烧焦”。

## 2. T43：相关候选在进入模型前丢失

已恢复首次和复测的model_call原始输出，两次均为`hypotheses=[]`，不是模型先给了正确计划再被字段校验删掉。

真实链路：

1. 西语查询`El robot está desconectado`返回15条，相关Wi-Fi条目rv-0271均排第14。
2. 当前candidate_k=15、final_k=12，rerank/grade/query_rewrite均关闭。
3. pack_hits按原排序保留前12条；SSE evidence展示全部15条，诊断模型只收到12条。
4. 真实模型输入的allowed_plan_ids中没有qa_rv_0271，正文也没有该条目；前列多为悬空、被困、回基站等不适用内容。
5. 模型返回空列表，_diagnose_outcome把空计划映射为R5，没有改检索或澄清的恢复环节。

离线回放实际候选：max_items=12时目标因item_limit排除；仅改15时目标进入证据。这个差分证明丢失位置，不证明简单增大条数能保证业务答对；条数增大仍会稀释5000字符总预算，其他案例相关知识可能排得更后。

上游排序在本次跨语言查询上不理想是实测事实；不能据此断言具体embedding模型不支持西语，尚未做检索器单变量对照。确定缺口是裁剪前缺少相关性/覆盖保证，裁剪后空方案没有恢复，以及展示证据和模型可见证据口径不同。

前次报告“召回后未生成指导”方向正确，但“适用性过严”只是当时假设。现在排除该假设作为T43直接原因。刚加的适用性约束让不相关候选不再被强行下发；应修候选供应与恢复路径，不能恢复随便选第一条的兜底。

## 3. T20复测：另有检索缺失及待确认分支丢失

复测没有输出那句危险否定描述，因此没有再触发R4，但两轮检索均未召回精准定位条目rv-0090。

模型给出rv-0087与rv-0218两个needs_confirmation假设，并写出需确认是否同层有基站、是否从基站出发及有障碍。filter_hypotheses将非supported候选全部丢弃，下游把空集合当R5。这里“需要问清楚”被压缩成“没有方案”，确实是适用性状态缺少后续处理；与T43的直接原因不同。

两条假设的supported_symptoms还多了一个`be`，但过滤先命中needs_confirmation，本次直接原因不是字符串精确匹配。不能因看到这个字段异常就倒置执行顺序。

## 4. 摘要与实际交接是两个未统一的出口

graph.summarize将摘要写入issue.latest_summary，并把issue.handoff.status设为prepared。该节点没有创建/提交人工审批案件，当前两单summary.case_id=null；不能把stage=escalate或观测outcome=escalated等同队列已受理。

现有业务审批路径与通用R4/R5摘要路径的完成条件不同。这不是“到了人工审批为什么还继续”，而是还没到真实人工审批。摘要并非丢失，缺的是被人工接收的状态与动作。若比赛定义摘要生成即终点可按该口径评分；若要求真正交给人工，则需统一出口，以案件进入队列且摘要关联成功作为完成条件。

## 必要修复方向

- T20安全：显式保存风险事实的肯定/否定/不确定与证据，补齐当前语法边界回归。
- 知识链路：在预算内优先保留相关候选；空方案区分未检索到、被裁剪、需要确认、确无适用知识，并提供受控补查/澄清。
- 交接：明确摘要prepared与队列submitted的不同；对需要真实人工处理的出口统一提交和验证。

重排、跨语言查询改写、增大候选预算属于可比较的实现选项，并非三个开关全部打开就能解决。应以T20/T43及既有正常案例的相同口径对照验证。
