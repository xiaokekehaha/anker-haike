# 验收矩阵

状态：待实现后执行。本次仅检查设计覆盖；以下不是已经通过的测试结果。

## 1. 测试层次与样本约束

- **D 确定性**：注入录制/固定结构化理解结果，调用真实接收→图→Store→snapshot，验证状态/顺序/幂等。不能只测独立字符串函数。
- **S 语义**：使用候选真实模型，检查实际传入的历史与输出的意图/目标/事实/回答。独立金标至少 60 组，12 个语义族各至少 5 组变体，覆盖多意图与否定，不把同句重复采样当独立样本。
- **I 集成**：真实 PostgreSQL、HTTP/SSE、刷新、取消、重试、重启和历史清理后统一启动。
- **U 界面**：实际前端行为与 snapshot 一致，时间、摘要版本、动作可见；不以截图数量代替结果断言。

建议 12 个语义族：历史回顾、步骤解释、事实补充、明确纠正、模糊纠正、换问题、返回旧问题、待办回答、步骤反馈、人工请求/状态、风险否定/主体、时间/长程指代。每族包含相近措辞但不同目标的反例。

## 3. 自动化不变量

确定性测试必须全部通过：

1. 同输入/动作/patch/effect 的幂等；同 ID 不同业务内容明确冲突。
2. seq 严格单调且 as-of 没有未来信息；消息时间不替代顺序。
3. 无增量/抽取失败不删事实；未明确效果不记 solved/not_solved。
4. 解释不消耗 pending、不增加步骤；纠正失效旧计划但保留执行历史。
5. issue/device 归属隔离；高危主体未知不能借新话题绕过约束。
6. 未确认产品、未分析图片、未实际转接都不能冒充已确认/已完成。
7. 摘要或模型旧输出不能覆盖有效新事实；已删除/到期数据不能由后台任务复活。
8. 主备模型必要事实集合一致；实际输入满足配置与模型窗口限制。
9. 公开 version、业务 context/issue revision、event seq 和 checkpoint_id 各司其职；未发布候选不可见。
10. 模型实际收到知识短原文及可追溯引用，当前操作依据不被历史累计顺序或旧产品证据污染。

## 4. 语义与体验指标

以下是提议的发布门槛，不是本项目已测得成绩：

- 至少 60 组独立多轮样本，普通意图/目标/所需状态变化的联合正确率 ≥95%；逐族披露分子分母，不能只报总均值。
- 安全主体、否定纠正、跨问题隔离及虚构人工成功场景必须全部通过；不能用其他简单样本抵消。
- 原始 7 轮样本逐轮通过；回答可有不同措辞，但必须回应问题、事实正确、动作真实。
- 澄清按“目标确实歧义时恰当追问”评分；不奖励对所有输入一律追问，也不以追问率越低越好。
- 输入“新问题”的回答不能只有旧安全转接；输入历史查询的回答必须包含所问历史事实，不能只说“我记得”。
- 真实模型语义样本使用与调提示词分开的留出集，记录温度/模型/prompt 版本；LLM judge 可辅助，争议样本人工按金标裁定。

性能：沿用当前 25,000ms run deadline 为总约束，正常非快捷自然语言常规最多一次语义抽取，再按需回复/诊断；不得暗中重复原 intake。发布前采集同负载下 P50/P95 首个有效回复、run 时长、输入 token 和模型调用数。任何 deadline 超限应明确记录；不只用先发一条无关安抚来美化首字延迟。额外延迟是否可接受依据同环境基线评估，未采集前不承诺数字提升。

## 6. 验收证据格式

每个案例记录 case_id、fixture_version、模型/Prompt/规则版本、输入 seq/时间、实际上下文引用、解释结果、状态 diff、最终回复/事件、断言及失败原因。敏感原文按当前脱敏策略处理。

D 通过证明确定性流程；S 通过证明所测样本上的模型效果；I/U 通过证明协议与实际交互。四类不可互相替代，规划文档的自检不计入上述通过率。
