# 调研 C：业内架构与运维（原始材料）

来源：后台调研 agent，2026-09-14 检索。**[已核实]** = 一手来源；**[媒体转述]** / **[未证实]** / **[推断]** 见标注。

## 关键结论

1. **成熟落地的几乎全是「专用模型 + 人审」的车险定损链路**（Tractable、CCC、Solera、平安、蚂蚁保）。消费电子售后的「用户拍故障照 → AI 判断」在公开资料里仍以**通用多模态 LLM 直接看图 + 转文字进上下文**为主（Intercom Fin Vision 最透明）。Apple / Dyson / iRobot / Roborock / Ecovacs / Samsung / Pixel **均未找到公开的「拍照 AI 诊断」功能证据** —— 这是行业空白，不是我们落后。
2. **架构上有充分证据支持「混合 > 纯 VLM」**：检测器 / OCR 先给结构化证据、VLM 只做推理与写报告，**幻觉率从 65% 降到 4%**（风机叶片巡检论文）；检索参考图 / 故障卡（visual RAG）在小样本域上把零样本 VLM 拉到接近满分；级联（廉价门控 → 贵模型）可省 27%–98% 调用成本。
3. **图像质量门控是所有成熟系统的标配**：经典 CV（Laplacian 方差、亮度、分辨率、部件覆盖）跑在端侧 / 前置，7 ms 量级。VLM 自己「主动发现输入有问题」的能力很弱（ISEval、MM-AQA 两篇基准都证明默认提示下几乎不弃答）。
4. **UX 共识**：前置拍摄引导 → 实时质检并指出哪张、为什么要重拍 → 把模型「看到的」回显给用户确认 → 不可逆动作前显式确认。文字与图片冲突时 VLM 默认偏信文字，需要单独设计。
5. **安全**：鼓包 / 冒烟 / 漏液属「停止排障、立即升级」的硬规则，Anker 官方博客与 CPSC / 纽约州指南一致。

### 1.3 设备排障与工业巡检

- **TechSee（Sophie AI）**：客户摄像头对着路由器，CV 识别**精确型号、端口 / 线缆 / 按键位置与状态、LED 指示灯、错误码、条码**，AR 覆盖指引；**few-shot 训练一个新设备「数小时」**；升级人工时保留视觉上下文。客户含 AT&T、DT、Vodafone。[[CV 页](https://techsee.com/computer-vision/)]
- **风机叶片知识增强 VLM（visual RAG）**：技术文档 + 参考图 + 指南构成知识库，「文本-图像混合检索 + 关键词感知重排」，30 张标注图上 RAG-VLM 达 100%，零样本同一 VLM 显著更低。[[2510.22868](https://arxiv.org/abs/2510.22868)]
- **风机叶片混合架构（Eyes / Bridge / Brain）**：YOLO 原生分辨率检测 → 确定性编码为网格空间 token → 4-bit Qwen-2.5-1.5B 生成 JSON 报告；**幻觉率 4% vs 零样本 VLM 65%**，专家评分 8.6 vs 3.3，**1.5B 模型在相同检测证据下报告质量高于 671B 通用 API 模型**。[[2605.26533](https://arxiv.org/abs/2605.26533)]
- **桥梁损伤 + Quality Guard Agent**：VLM 生成损伤描述 → 小模型**拒绝低质量 VLM 输出** → 规则引擎映射到五级修复优先级。[[2605.27452](https://arxiv.org/abs/2605.27452)]
- **InspectorGPT**：以「无缺陷参考图 + 待检图」做**对比推理**，并指出「面向推理的后训练可能让异常判别能力坍塌」。[[2608.29783](https://arxiv.org/abs/2608.29783)]

## 2. 架构模式比较

| 模式 | 典型实现 | 优点 | 风险 / 成本 | 证据 |
| --- | --- | --- | --- | --- |
| **(a) VLM-only** | Intercom Fin Vision：图 → 结构化文字 → 入上下文 | 上线快、零配置、覆盖长尾 | 幻觉率高（零样本 65%）；小缺陷被缩放抹掉；域知识不足时强模型优势消失；**不会主动说「图不清」** | [2605.26533](https://arxiv.org/abs/2605.26533)、[2605.13173](https://arxiv.org/abs/2605.13173) |
| **(b) 专用检测器 / OCR + VLM** | 风机 Eyes/Bridge/Brain；TechSee 设备 / LED 识别；蚂蚁 OCR + 高分辨率编码器 | 定位 / 读数交给专家模型，VLM 只推理 → **幻觉 4%**；小模型即可；可解释（框 / 热力图） | 需每品类标注与维护检测器；两套模型运维 | 同上 |
| **(c) VLM + 视觉检索（参考图 / 故障卡）** | 风机 RAG-VLM；InspectorGPT 参考图对比；CLIP/SigLIP 检索示例做 ICL | 无需训练即可注入域知识；可解释（「与故障卡 #12 相似」）；many-shot ICL 对 GPT-4o / Gemini 呈对数线性增益 | 检索质量决定上限；**开源小模型不从示例中获益**；上下文成本上升 | [2510.22868](https://arxiv.org/abs/2510.22868)、[2405.09798](https://arxiv.org/abs/2405.09798) |
| **(d) 级联：廉价门控 → 贵模型** | 模糊门（MobileNetV3 + Laplacian 通道，7 ms/CPU，F1 0.98）；SAFE-Cascade（VLM 调用 −26.9%，精度持平）；FrugalGPT（最高 −98% 成本） | 省钱省延迟；差图不进贵模型 | 级联「先付廉价模型」是结构性成本，理论分析显示**生成前路由器在 80% 数据集上优于级联**；门控需校准 | [2606.25838](https://arxiv.org/abs/2606.25838)、[2606.19646](https://arxiv.org/abs/2606.19646)、[2305.05176](https://arxiv.org/abs/2305.05176) |
| **(e) 集成 / 第二意见 → 分歧即问用户** | CUSP：多 VLM 语义空间池化，集体不确定性 + JS 散度度量冲突；无需 logits | 错误检测 AUROC 0.764（比多数投票高 4.7–15.8 点），弃答 AUARC 0.889；池化预测 +5.6–13.0pp | 成本 ×N；多智能体只改善弃答并带来精度-弃答权衡，**根因是校准而非推理深度** | [2609.05708](https://arxiv.org/abs/2609.05708)、[MM-AQA 2604.14799](https://arxiv.org/abs/2604.14799) |

**[推断] 行业最优实践 = (d)+(b)+(c) 叠加**：前置经典 CV 质检 → 轻量分类器判「是不是我们的产品 / 哪个部位」 → 检索故障卡与参考图注入 → 主 VLM 输出结构化 JSON → 低置信 / 高风险走 (e) 或人审。Tractable / CCC / 蚂蚁的公开信息与此一致。

## 3. 图片质量门控

**经典 CV（首选前置）**
- 模糊：Laplacian 方差（对失焦敏感）+ FFT 高频能量比（对运动模糊敏感）组合；Edge-Prior 门控把 Laplacian 幅值作为辅助通道喂 MobileNetV3，17MB ONNX、**7ms、F1 0.98**，用选择性预测把「不确定」单列 [[2606.25838](https://arxiv.org/abs/2606.25838)]。
- 曝光 / 分辨率 / 主体覆盖：Inspektlabs 的 blur(0–5)、luma(1–5)、resolution、zoom、**parts detected**、Q_score 是可直接借鉴的参数集。
- 医疗远程照相 TrueImage 2.0：1700 张临床标注训练，模糊 AUC 0.84、光照 0.70；前瞻试验**差图患者 −68%**；差图成因分布：模糊 10%、光照 12.3%、取景 9.1% [[2209.09105](https://arxiv.org/abs/2209.09105)]。
- 反欺诈同层：翻拍屏幕 / 打印检测（Sightengine 单分 0–1）；AI 生图检测（淘宝、Zendesk Sentinel、SynthID）。

**VLM 做质量判断**
- Q-Bench / Q-Align：用 good/poor 两 token 的 softmax 概率量化，非自然畸变上优于 NIQE；但在真实畸变与分布偏移下可靠性下降 [[2607.01973](https://arxiv.org/html/2607.01973)]。
- **VLM 不会主动质疑输入**：ISEval「无引导时难以主动发现有缺陷前提」；MM-AQA「标准提示下 VLM 几乎不弃答，连简单置信基线都更好」，需要**弃答感知训练**而非更多提示 [[2508.04017](https://arxiv.org/html/2508.04017v1)、[2604.14799](https://arxiv.org/html/2604.14799)]。
- 压缩 / 小模型在视觉损坏下更脆弱（SmolVLM2-500M 否定题崩塌 −33pp）→ **[推断] 端侧小 VLM 只适合粗筛，不适合当质量裁判**。

**重拍引导设计**：实时（拍摄中）优于事后；**指出哪张、什么问题、怎么改**（「太暗，请开灯或靠近窗；请距离 50–100cm、不要倾斜」）；缺视角用「部件覆盖」列出还缺什么；翻拍 / AI 图直接提示「请拍摄真实物品」。

## 4. 拍照引导与确认 UX

1. **前置拍摄指南**：Solera 按 VIN 生成车型遮罩；平安要求全貌 / 特写 / 细节 / 多角度四类；ClaimSnap 宣称 5 步（全景、损伤区、细节、**序列号 / 型号铭牌**、环境）。
2. **渐进式索图**：「请拍设备底部 / 铭牌」应由**缺失部件列表**驱动而非固定脚本。JDDC 2.0 表明图片主要用于**型号判别与故障指示** → **铭牌照是高价值第一张**。
3. **回显确认再行动**：Google 会话设计准则——高置信 + 低后果用**隐式确认**（「我看到滚刷缠了头发，下面教你清理」），不可逆 / 高代价（发起退换、判定责任、安全升级）用**显式确认**；成批确认而非逐项。
4. **图文冲突**：VLM 偏好从 +56.8%（偏图）到 −74.4%（偏文）不等，简单题偏信文字、难题偏信图像；缓解手段：显式冲突解决指令、**先分别分析两模态再融合** [[Mixed Signals 2504.08974](https://arxiv.org/abs/2504.08974)]。**[推断]** 售后场景应把「用户说 X、照片显示 Y」作为一等输出字段并回问用户。

## 5. 评估与运维

**金标集与标注**
- 保险定损标注 schema：部件分类 + 框 / 分割 + 严重度（minor/moderate/high）+ 修 / 换决策；人审反馈回流再训练。
- **[推断] 售后故障照 schema**：{产品型号可见?, 部件, 现象, 严重度, **可判定性（可判 / 需补图 / 不可判）**, **危险标志**, 图质量标签, **用户文字与图是否冲突**}。可判定性与危险标志两列是别家 schema 里缺、而客服最需要的。
- 一致性：Cohen's κ（0.61–0.80 实质一致、>0.81 近乎完全）；VLM 幻觉标注实践中人审 100–500 条抽样，复杂场景幻觉率常见 10–30%。

**指标**
- 部件 / 现象准确率、可用判定准确率、幻觉率（忠实性 vs 事实性两类）、弃答率与**过度弃答**、选择性预测的覆盖-风险曲线（AUARC）。
- PROVE：用场景图 + 可执行程序同时度量**有用性与真实性**，发现「很少有 VLM 两者兼顾」[[2410.13121](https://arxiv.org/abs/2410.13121)]。
- 置信分层参考（文档抽取域）：>0.85 与专家一致 >95%，0.70–0.85 约 85%，<0.70 转人工。

**在线监控与回归**
- LLM / VLM-as-judge 跑在 CI（prompt / 模型变更回归）与生产 trace 抽样上，低分 trace 入回归集。注意 **VLM judge 能排序不能打绝对分**，且存在「未看图也打分」的信息量偏差 [[2604.25235](https://arxiv.org/html/2604.25235v2)]。
- 用户纠错信号（「照片里不是这个」）与人工坐席改判是最直接的飞轮：平安「核损员转型系统训练师」、CCC「AI 与估算师互相学习」。**[推断]** 需把「AI 判定 vs 坐席最终判定」结构化存档才能形成训练集。

## 6. 安全

- **硬规则来源**：Anker 官方博客——鼓包即「立即停用、勿拆、勿再充电 / 使用、按电子垃圾回收」[[Anker UK](https://www.anker.com/uk/blogs/power-banks/what-to-do-with-expanded-battery-pack)]；纽约州 / CPSC 指南：鼓包、嘶响 / 爆裂声、异味、冒烟、漏液 → 断电、移至安全处、必要时报警。
- **视觉识别可行性**：火 / 烟 FIRE-TASTIC 用任务感知检测器引导零样本 VLM、VLM 负责用语义降误报；SmokeBench、DetectiumFire 可作评测集；ForestFireVLM-7B 微调后 76.6% vs Gemini 2.0 Pro 65.5%。
- **流程共识**：危险信号 → 停止排障脚本、输出固定安全话术、升级人工；AI 不得自主给出「继续用」的判断。**[推断]** 危险识别应设计为**高召回、低阈值、人工兜底**，误报成本（多问一句 / 多转一次人工）远低于漏报。
