# R7 症状问诊解决方案评估

## 结论

建议沿现有 diagnose.decision 模块完善“证据是否足以选择下一步”的决策。保留用户事实与问答记录作为可追溯输入，由统一入口派生诊断和下一步；没有必要立即引入概率假设系统或重写编排框架。

## 当前实现与历史 spec 的差异

| 历史问题 | 当前代码状态 |
|---|---|
| 旧 symptom code 覆盖 narrowed | reducer 改用 accept_answer，旧事实不会无条件覆盖答案；显式更正有独立失效标记 |
| 关键词漏词否决模型事实 | decide_symptoms 先消费事实和问答，词面匹配仅提供正向证据 |
| 必须问到唯一候选 | 多个候选对应相同非空计划集合时可继续 |
| 两次有效提问也触发 R7 | 判别问答改为连续两次 unknown 停止；产品澄清预算另行处理 |
| R7 一律称产品不明 | 摘要根据实际澄清原因、诊断原因渲染，并带问答记录 |

证据位置：orchestrator/app/diagnose/decision.py、orchestrator/app/conversation/reduce.py、orchestrator/app/sessions/clarify.py、orchestrator/app/escalation/summary.py。

## 需要修正的 spec 推论

1. **观察和假设应分开。**“启动不了”和“没有充电指示”可以同时成立。power_failure 与 charging_failure 不必互相覆盖。真正冲突应指同一设备、同一时间范围、同一属性存在互斥证据。
2. **唯一候选不是确诊。**候选来自有限配置；唯一解只表示配置内收敛，还需检查证据有效性、产品适用范围及动作前置条件。允许保留“其他/证据冲突/覆盖不足”，避免强行归入已有类别。
3. **零检索不自动构成错误。**已有适用的审核计划可以提供步骤；关键是动作有依据。风险升级、用户明确要求人工或无法构建有效查询时，不应被强制检索阻塞。模型在下一轮能写出三步建议，也不能证明这些建议经过验证或适用。
4. **单一裁决入口不等于只存假设。**保留原始事实、引文、问题 ID 和来源；假设是可重算投影。否则失去纠正和回溯依据。未经校准的模型 confidence 不适合直接当概率计算熵。

## 推荐实施顺序

### 第一阶段：补足决策与摘要的可解释性

扩展现有 DiagnosticDecision，明确记录：

- 当前可执行步骤及计划版本；
- 仍缺少的前置条件与待澄清问题；
- 依据的事实/问答引用；
- 停止原因：用户无法回答、系统覆盖不足、证据冲突、计划耗尽或安全限制。

摘要直接消费该决策快照。当前 hypotheses 只从 plans_ranked 取值，问诊阶段停止仍可能为空；应分别输出“已知现象”“候选判断”“待确认信息”。已给出但未收到反馈的步骤不能列为已执行。

### 第二阶段：把提问和停止条件绑定到下一步

对每个候选计算满足产品、前置条件、风险限制且未被耗尽的动作。存在共同可执行动作时，可先执行该动作，再用反馈区分后续路径。

例如候选 A 的动作是 {供电检查、检查 A}，候选 B 是 {供电检查、检查 B}：当前集合相等判断不能利用共同步骤。只有确认“供电检查”在两种情况下的操作内容和条件都兼容，才可安全复用，不能只比较名称。

优先询问会改变动作选择的问题，并跳过已有直接证据回答的问题。记录每轮是否新增有效事实、解除动作前置条件、改变候选/动作集合。重复回答、无法解析、unknown 分开统计；澄清总预算按 issue 和当前证据版本绑定，保留明确硬上限。硬上限触发时记录真实停止原因，不伪称产品不明。

当前连续 unknown 计数可继续作为简单策略；暂不引入没有校准依据的熵计算。

### 第三阶段：按实际需要深化证据管理

事实和问答由现有 reducer 管理；每条派生判断记录依赖哪些事实、问答与配置版本。用户更正时只失效依赖该证据的判断，追加独立症状保留旧观察。产品切换和 taxonomy 版本变化要重算或明确迁移。

状态字段作为展示/兼容投影；路由只读取统一决策。保留已存在的检索、审核计划和操作约束，实现知识缺口时补检索、有适用方案时继续、需要人工时给出可审计摘要。

## 验收场景

- “X10 Pro Omni 启动不了”：已有适用步骤时不重复询问能否启动。
- “启动不了→不能→不能”：旧检查点与新会话均保留原观察和问答，进入适用排障。
- 多候选拥有共同可执行步骤：不强求唯一故障标签；只有部分候选允许的动作不得提前下发。
- 问答仍产生进展：不因为累计两问触发 R7；无进展达到预算时明确真实原因。
- 补充异响保留原观察；更正为另一现象撤销相关推断；换设备不串用证据。
- 缺少判别问题归因系统覆盖；摘要即使没有 plans_ranked，也保留已知现象和问答。
- 用户报告焦味、明确要求人工：遵守相应停止/转人工路径，不以强制检索或继续操作延迟处理。
