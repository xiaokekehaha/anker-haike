# 链路 B 检索改造

## 用户授权与目标
用户在链路 B 修改必要性分析后要求“开始修改”。落实候选保留、充分性驱动的一次补查和两轮最终证据选择；复用现有范围约束、模型路由与预写排障计划。

## 实现边界
- 分开 candidate_k、final_k 与上下文预算，保留排序所需正文和来源，展示摘要继续受限。
- 评分改为质量标记和充分性建议，不硬删除候选；相关但不足、无相关证据、评估未知可受控补查，真实服务故障和空范围独立处理。
- 文本改写与图片补查共用一次名额；合并两轮后联合选择最终证据，防止新增有效证据被首轮条数挤出。
- 改写保留产品、有效症状、否定与纠正；已有模型重排输入增加标题/正文，仍作为独立开关。
- 新的补救能力配置明确，保留独立增强开关；不使用未重新验证的模型实验结果宣称准确率收益。
- 更新相关评测入口/文档，使候选与最终证据口径一致；完整补查行为通过真实会话编排的替身测试验证。

## 验证
- 回归：第8名候选可进入重排；已有相关但不足仍补查；评分误判不删除首轮证据；充分不补查；二轮有效证据进入诊断；故障/空范围/改写失败不破坏首轮结果；图文共享名额。
- 复用 FakeChatModel、fake WeKnora、conversation_runtime；不调用真实模型或知识库。
- 运行所有修改/受影响的测试文件与 make lint；不运行全量 pytest、构建、发布或提交 Git。

开发开始后本文件保持不变，细化与复核写入 addendum.md。
