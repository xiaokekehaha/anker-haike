# 链路 B 检索改造结果

2026-09-18。实现已完成，使用替身验证真实会话 HTTP 编排，没有运行真实模型/知识库评测。

召回指取回候选片段；重排指重新评价候选与查询的相关性；充分性指证据是否足以支持当前问题的排障方向。

## 数据流程

```text
用户输入 -> intake -> 当前产品 + 有效症状
                         |
                         v
              基础查询 + KnowledgeScope
                         |
                         v
        WeKnora hybrid-search：关键词 + 向量 + RRF
                         |
                         v
          每库候选 15 条，正文最多 4000 字/条
                         |
        可选同义查询融合 / 分库模型重排
                         |
                         +---- 本地适用故障卡
                         |
                         v
        按最终证据预算选代表 -> 可选充分性评估
                         |
          +--------------+-----------------+
          |                                |
       sufficient                insufficient / none / unknown
          |                                |
          |                  服务正常、范围非空、名额/预算允许
          |                                |
          |                     图片观察 或 受控文本改写
          |                                |
          |                     第二轮召回（最多一次）
          |                                |
          +--------------+-----------------+
                         |
                         v
           稳定 ID 去重，合并查询来源
                         |
                         v
           轮次/来源交错，给反证保留位置
                         |
                 可选父块扩展
                         |
                         v
      最多 12 条，总证据块 5000 字，单条正文最多 800 字
          包含标题、来源、版本、轮次、工单结果
                         |
                         v
        synthesize -> 允许的排障计划 -> 已审核步骤
```

图中的候选数是应用请求和保留预算，不代表 WeKnora 内部向量/关键词召回总数。模型评分和重排仍受各自开关控制。

## 已解决的问题

| 原问题 | 当前实现 | 验证方式 |
| --- | --- | --- |
| API 返回第 8 名在重排前被裁掉 | candidate_k 与 final_k 分离，展示摘要不再限制候选池 | 假 WeKnora 返回 12 条，真实适配器和重排编排把第 8 条提升到首位；评分 I/O 用替身 |
| 重排只能读 400 字摘要 | 输入文档标题及最多 4000 字命中正文 | 相关标记位于摘要之后，仍进入重排和所选模型正文 |
| 已有命中阻止不足补查 | coverage 与服务状态分开；不足、无相关证据、评估未知可补查 | HTTP 回归覆盖非空候选、充分、评分失败、无可用范围及服务故障 |
| grade 误判删除候选 | grade 只标记，不硬删除；缺口必须来自有效症状 | 首轮被判 irrelevant 的证据与第二轮新增证据均进入真实诊断调用 |
| 故障卡一命中就阻止补查 | 故障卡参与同一次充分性评估 | 不足时补查，充分时停止；知识库禁用时仍受最终正文预算限制 |
| 第二轮结果追加后挤不进前 12 | 先合并，再按轮次/来源交错，优先给新增轮次代表留位置 | 首轮 15 条后新增的证据实际出现在诊断模型输入与引用中 |
| 长父块只取开头 | 围绕命中子块取窗口，句末裁切不丢掉可容纳的命中内容 | 命中位于长前言之后的父块测试 |
| 改写改变部件/纠正/否定 | 删除“刷子→滚刷”，限制同义多查询品类，增加局部否定和纠正检查 | 否定、纠正、部件歧义及非扫地机查询回归 |

最终选择保留各来源内部已有排序，不比较不同来源的原始分值，也没有新增跨库统一模型重排。第二轮沿用已有不调用重排模型的预算规则。轮次交错保障新增证据进入候选选择，不能证明新增内容一定相关。

## 配置与运行边界

主配置为 `config/retrieval.yaml`，版本 `2026-09-18.1`：

| 配置 | 当前值 | 含义 |
| --- | --- | --- |
| retrieval.candidate_k | 15 | 每库每查询保留的候选数；多查询融合后每库也受此限额约束 |
| retrieval.final_k | 12 | 两轮、各来源及故障卡的最终条数上限 |
| retrieval.context_chars | 5000 | 完整证据块字符预算，含来源等标签；不是整个模型请求的 token 预算 |
| retrieval.item_chars | 800 | 单条模型正文上限；界面展示摘要仍最多 400 字 |
| query_rewrite.enabled | false | 开启后构成“充分性评估 + 至多一次文本补查”；不需要同时开启 grade.enabled |
| grade.enabled | false | 单独启用充分性观测，不自动启用文本改写 |
| grade.second_round | false | 可选第二次充分性评估；不会触发第三轮检索 |
| rerank / multi_query / faq / parent_expand.enabled | false | 独立实验开关 |

候选保留和上下文选择是默认路径的改动。图片补查继续使用已有分支，服务正常且没有充分结论时可消费唯一名额；文本改写必须启用 query_rewrite。图片和文本共用名额，失败不递归。

评分先使用最终证据预算裁剪，再缩小为评分输入，不得从已裁掉的正文尾部得出充分结论。启用父块扩展时，最终诊断正文可能增加相邻上下文，评分仍只代表当时实际评估的片段。

全局会话 deadline 和剩余时间门槛本轮未调整：评分需剩余至少 6 秒，文本补查决策需至少 8 秒，第二轮检索有 3 秒上限。真实模型延迟下的跳过率仍需测量。`models.yaml` 将 grade 输出预算从 256 调至 1024，以容纳代表证据的结构化判定。

旧的 retrieval.top_k、grade.keep_min 已移除，六份可执行评测预设同步迁移；历史 release 快照和历史评测报告保持为历史记录。自定义配置也需要迁移这些字段。

## 追踪与评测

- 每次查询记录 API 返回数、范围过滤后数量和候选数；融合/重排保留现有追踪。
- grade_result 记录实际评估的 ID、充分性及经过有效症状白名单过滤的缺口。
- rewrite_decision / rewrite_result 区分停止原因、评估未知、改写拒绝和补查采用情况。
- context_selected 记录最终 ID、所属轮次、字符数、被裁短 ID，以及 item_limit / char_limit / empty_content 排除原因。
- synthesize 的引用白名单与实际传入的证据集合一致。步骤生成阶段可能再加入预写计划引用；该引用不能被统计为检索召回成果。

单轮 `haike-kb eval` 现在使用相同的候选与上下文选择，片段标记必须属于金标文档且存在于模型可见正文；报告记录配置和 single_round 范围。启用 query_rewrite 时此入口明确拒绝运行，避免把未覆盖的补查当成已评测。它仍不覆盖 intake、故障卡与两轮编排。

验证结果：26 个相关测试文件，233 passed、1 skipped；跳过项需要真实知识库。`make lint` 和 `git diff --check` 通过。覆盖真实 HTTP 会话、假 WeKnora、候选重排、图文共享名额、二轮失败保留首轮、第二次评分不产生第三轮、回放及既有诊断流程。

这些结果证明控制流和输入边界，不代表真实准确率提升。模型增强默认继续关闭，真实多品类金标对照仍是启用依据。
