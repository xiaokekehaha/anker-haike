# 测试方法与复现

## 输入和停止规则

T1–T63均新建独立会话，首轮发送官方工单正文和本地附件。正文中的外链只作为原文保留，不额外下载或当成已上传视频。仅当系统明确索型号时，使用官方独立产品列补充；不补未知事实、故障结果、购买材料。

操作卡统一模拟not_solved（未解决）；这不是实机操作。question（独立问题）、material_request（索材料）、确认或人工边界停止。最大19轮，本轮未触发轮次上限。第一轮合格与整条已观察路径合格分别判断。

6个补测仅T4/T56/T58各重复两次，使用同样策略；每次单独新会话，不替换主层，不混入63分母。主层并发3，每个重复批次并发1，两个批次同时启动；并发差异也是有限重复的解释边界。

## 评分和中文记录

合格：已观察范围内方向、事实、来源与权限合理，允许停在必须澄清/材料/人工。需改进：已经发生可指明的答偏、重复、未答问题或错误执行。待核：官方资料适用性尚不能确认。知识缺口即使诚实答复合格，也不算用户问题已经解决。

每案原文、系统实际英文、卡片title/instruction/context/expected_result/caution/options/media均保留；逐轮中文为业务译述，压缩礼貌语与重复技术字段。模拟输入和评审意见明确分开。复用历史完全匹配片段的译文后，本轮逐案重新阅读；新片段人工补译，评分重新填写。

通用知识用于核验对象、否定、条件和证据强度。例如“充过电”不能自动证明“已充满”，单张照片不能判断闪烁，“抱怨差”不能直接推成画质差。具体产品功能、步骤与售后政策仍核官方资料，不能用常识补厂商承诺。

## 版本

当前容器匹配3c362c8。工作区341ab25有两个未部署文件差异，详见addendum。驱动对Git归档中全部被测文件计算哈希，逐一匹配容器；每案核容器身份，前后核全部运行文件。只读补采核同一会话，不发送新消息。

## 命令

Makefile没有63案专用入口，复用现有HTTP评测脚本，后端通过uv读取根.env。每次必须新输出目录。

```bash
make health
cd orchestrator
uv run --env-file ../.env python ../docs/planning/2026-10-11-1712_official-63-evaluation/evaluate_long.py --output /tmp/haike-new-63-round --concurrency 3
```

驱动绑定已核实的运行基线3c362c8。未来版本变化时应先建立新轮次并修改其基线核对，不能删除门禁强跑或覆盖本轮。

本轮离线文档生成顺序：prepare_review.py生成候选译文；review-input.json保存人工译述与裁定；freeze_review.py合并裁定；export_report.py生成69份过程和统计；validate_report.py核正文、卡片、链接、哈希和统计。原始证据run/repeat-1/repeat-2不改写。collect.py仅补采63主层；补测即时采证完整，enrichment中的补测文件是呈现副本，文件内明确注明来源。

没有修改业务实现，因此没有运行后端/前端回归测试或全量CI。文档和脚本执行的校验结果另存，不能等同业务正确性证明。
