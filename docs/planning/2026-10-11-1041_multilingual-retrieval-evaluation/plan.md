# 多语言检索：标注与分层对照方案

日期：2026-10-11。范围：方案设计；未改运行配置，未运行真实模型或知识库评测。

## 1. 问题与已核实边界

推荐顺序：补标注 → 人工英文查询验证 → 模型英文表达验证 → 充分性触发与补查验证。是否启用由检索收益、事实忠实性及最终诊断共同决定。

- `config/retrieval.yaml`：query_rewrite、grade、rerank 默认关闭。
- `orchestrator/app/sessions/graph.py:2023`：grade_enabled = grade.enabled or query_rewrite.enabled。因此改写会隐式启动充分性评估，并非必须同时打开两个开关。
- `orchestrator/app/diagnose/rewrite.py`：允许无命中、不足、无相关证据、评估未知时补查；服务不可用、范围为空、预算不足等跳过。图片补查与文本补查共用一次名额。
- `orchestrator/app/bakeoff/scoring.py:115`：拒绝或无改写结果记 0，再检查 must_contain_any。历史 75% 不能解释为线上四分之一工单会被改错，需区分误拒、输出错误和召回无收益。
- `data/eval/tickets/cases.yaml:21` 和旧 remaining_work.md 记录过英文术语改写 9/12 → 9/12。该历史实验不是本方案的线上多语言对照，但说明不能预设翻译必然有效。
- T20、T37 有 qa_gold；T21、T36、T43 没有 qa_gold/qa_exact。现有 `knowledge/eval.py` 会跳过无金标工单。不能把旧报告称为覆盖全部 63 单。
- 现有 `make kb-eval ARM=...` 的 ARM 只是报告标签，evaluate 只执行一次 search_round；case_state 未填线上抽取的 symptoms，使用原文回退查询。打开 query_rewrite 后跑此命令不会自动测到图中的改写或 grade。
- 当前 intake 主入口为 `conversation/interpret.py`；不能只修改旧 `intake/extract.py`。

## 2. 先用 T43 区分三类故障

原始描述：`El robot está desconectado.`；已知产品 PN：T2351。

候选忠实英文表达：`The robot is disconnected.`。`offline` 是否可作为等价表达需要结合上下文标注；不能从该句自动推导路由器故障、密码错误或 Wi-Fi 硬件损坏。

在同一产品范围、同一知识库快照下比较：

1. 线上抽取后实际查询。
2. 保留完整问题原文的查询。
3. 人工忠实英文表达。

若 2 优于 1，先修抽取导致的上下文丢失；若 3 优于 1/2，再实现英文检索表达；若三者均失败，检查正确 Q&A 是否存在、产品范围是否排除、索引是否覆盖，不能靠继续改写解决知识缺口。

命中只说明候选相关，不能证明无需澄清即可执行 Q&A 的操作。

## 3. 标注集

先复用 cases.yaml，建立独立的多语言检索标注文件（拟新增 `data/eval/retrieval_multilingual.yaml`），不把尚未审核的条目写为生产事实。

每个 case/issue 记录：

- ticket_id、issue_id、language、原始文本引用、产品范围、有效症状与否定、已做动作、错误码。
- relevance_status：answerable / needs_clarification / no_relevant_qa / uncertain。
- relevant_qa_ids：确有相关性的条目集合；可并列多个等价答案。required_evidence_groups 表示多症状各自需要覆盖的证据组。
- forbidden_qa_ids 与原因：例如产品不适用、连接失败与反复掉线混淆。
- human_query_en：只看用户事实生成的忠实英文表达；保留否定、对象与条件，不复制目标 Q&A 答案措辞来提高成绩。
- 每个 Q&A 判断的标题/正文引用、资料版本、标注人和复核状态。

重点补 T21、T36、T43；复核 T20、T37。不能强行为每单指定答案：原文不足或知识库缺内容应显式标记。Q&A 对不上时记录缺口。

标注先于实验冻结；判读时隐藏实验组与候选排名。人工复核有争议的映射、全部新增收益及退化。63 单已多次用于调试，只是回归集；从新增真实工单建立未用于调提示词的留出集。合成翻译和对抗样本单列，不计为新增真实样本。

## 4. 对照设计

第一阶段先测检索表达，不引入触发判断：

| 组 | 查询与处理 | 要回答的问题 |
| --- | --- | --- |
| A | 冻结的线上原查询，一轮检索 | 当前基线 |
| A-full | 问题完整原文，一轮检索 | 是否抽取丢失信息 |
| H | 人工忠实英文，一轮检索 | 英文表达是否有潜在收益；仅诊断参考 |
| B | 模型生成英文表达，一轮检索 | 模型能否接近 H，替换查询是否退化 |
| B-union | 原查询与模型英文各查一次，按生产规则合并 | 增量查询的收益是否抵得上延迟和候选挤占 |

第二阶段在 B 有收益后测实际策略：

| 组 | 处理 | 要回答的问题 |
| --- | --- | --- |
| C | 现有 query_rewrite 开启，其余一致 | 当前改写链路实际能否改善 |
| D | 首轮原查询，充分性评估触发英文补查 | 新英文表达与触发器组合能否改善 |

第一阶段的双查询属于离线对照，不直接加入线上额外名额。第二阶段复用一次补查额度，保留图片补查优先级。

每组固定：知识库及索引版本、产品范围、候选数 15、最终条数 12、上下文 5000 字符、重排设置、模型别名与真实返回模型、prompt/config/code 版本。记录工作区未提交差异摘要；执行时重新冻结，不把本次行号当永久接口。

先固定同一份 intake 状态比较查询策略，隔离抽取波动；再将胜出策略接回完整链路，验证 intake、grade 和诊断的累计影响。英文表达、grade 与改写至少独立采样 3 轮，逐轮报告并记录降级、超时；重复调用不是新增独立工单。

## 5. 指标与归因

现有报告名 recall@k 实际是“任一金标是否命中”的工单命中率（Hit@k）。新报告明确命名：

- Hit@5 / Hit@12：可回答工单中前 k 个候选包含任一相关 Q&A 的比例。
- Recall@k：每单相关 Q&A 集合被召回的比例，适用于多个答案；多症状另报证据组覆盖率。
- 首个正确条目排名；最终进入模型上下文的正确证据覆盖率，不能只统计检索返回。
- 新增命中、原本命中却丢失的逐单清单；按语言及错误码/现象单拆分。
- 忠实性：否定翻转、新部件/原因/动作、对象错误、数字/型号/错误码变更、已做与未做混淆；误拒单独统计。
- grade 漏触发（有可补回证据却判足够）与无效触发；unknown、预算跳过、图片占用名额、服务故障分别计数。
- 无答案单错误进入排障的次数；正确召回后最终是否选对方向、是否需要澄清、是否新增错误操作。
- 延迟 P50/P95、实际调用数和成本。记录补查挤占最终综合预算造成的降级。

评估实际策略时，被拒绝、超时、未触发的案例均保留在原分母中，按其回退结果计分；不能只报成功改写子集。原始日志保存候选及各阶段排名，以区分“没召回 / 被裁掉 / 不适用 / 诊断没用上”。

## 6. 最小实现方向（实验通过后）

英文检索表达是用户事实的派生数据，只供检索。原始 quote、facts、symptoms、型号范围继续保留。表达绑定 active_issue 与有效事实版本，事实更正或切换问题后重新计算，禁止旧翻译继续生效。

先在评测层实现独立英文表达生成，便于冻结输入与归因。只有独立路径证实有效，才考虑并入现有 intake 调用减少一次请求；并入后需重新验证抽取准确率、输出预算与端到端延迟。

生成约束：只做忠实英文表达，保留否定、对象、条件、时间关系及事实状态；不给故障下结论；失败时回退原查询。型号和错误码使用原始结构化值，范围始终由服务端控制。翻译绑定事实引用只证明来源，不能代替语义忠实性审核。

旧 validate_rewrite 不能直接充当多语言安全证明：NEGATIONS/PARTS/FORBIDDEN_NEW 以中文为主，shares_anchor 的任意两字符重叠可能偶然通过，且撇号过滤会误拒英文缩写。需用跨语言正反例明确修改范围，保留防止新增事实的约束；不通过关闭全部校验换取通过率。

同义词表不是首轮前置工程。只在稳定、反复出现且经人工确认的术语映射有收益时，补小型领域词表；避免把 `offline`、`cannot connect`、`keeps disconnecting` 当作无条件互换。自动生成全量多语词表、改 embedding、启用 rerank 均属后续可选复杂度，应分别评估。

## 7. 建议门槛与交付顺序

以下是待实验前冻结的建议门槛，不是已有性能结论或零风险保证：

1. 当前回归集与多语言对抗集中，严重语义漂移、错误码/范围变化、新增错误操作均为 0；出现任一例先修复再评。
2. 非英语可回答工单每轮新增命中均多于丢失；已命中的英语工单和精确码路径无新增退化；最终上下文覆盖与诊断正确性同步检查。
3. 留出集保持收益，不能靠 T43 一单证明泛化；小语种样本过少时报告 n/N 与不确定性，只支持有限试用，不能直接全量开启。
4. 上线前结合当前服务延迟目标确定允许的新增 P95 和成本上限；本轮未测量，不能凭各阶段预算之和宣称满足目标。补查不得导致最终诊断超时增加。

交付一：冻结金标与 A/A-full/H 报告，先回答“语言、抽取还是知识覆盖问题”。

交付二：B/B-union 报告、忠实性失败分类、FakeChatModel 与 fake_weknora 的相关单测。

交付三：C/D 触发与端到端报告，给出维持关闭、限非英语启用或更广启用的具体结论。受限策略需要显式配置；现有布尔开关不具备分语言灰度能力。

实施涉及后端时运行 make lint 与相关测试文件；涉及契约时改 Pydantic 源并 make contracts。真实实验走独立评测入口并限定样本和次数，单测不访问真实模型或知识库。用户要求提交时才执行提交前 CI。

本次方案交付不等于已完成标注、实验或上线验证。
