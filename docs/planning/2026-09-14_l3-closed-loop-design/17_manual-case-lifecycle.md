# 人工案件操作与会话同步

## 缺口

原 close/reopen API 只修改案件表，没有更新用户会话检查点或发送 case_changed；管理台也没有调用入口。人工结案后，用户可能仍看到等待审核或仍可提交的旧卡。用户页面只恢复自己发起的 run，空闲时不会发现人工处理产生的新 run。

## 实现

- 管理台提供人工结案、重新受理入口；执行中禁止结案，版本冲突返回 409。
- 存在原会话时，操作通过内部 case_command 进入既有输入保留、run、checkpoint 和持久事件链路。按案件的 issue 恢复状态，避免处理另一问题。API 在正常 run 提交完毕后才返回成功。
- 案件事务记录确定性的操作编号。数据库提交后、检查点提交前发生中断，恢复不会重复重开计数。与同一编号冲突的动作或操作者被拒绝。
- 结案与重开都使旧卡失效，清除方案确认和旧办理意图；保留业务对象与原执行回执。重开等待用户补充当前问题，不自动重办。未消费的旧审批不得越过新案件状态继续执行。
- 会话过期后的保留案件仍允许人工处理，只写案件与审计记录，不虚构用户通知。
- 用户页面有案件时每五秒检查变化，隐藏页面暂停，返回可见时检查；遇到外部运行接续现有事件流。后台响应不能覆盖期间发生的新输入或切换会话。人工输入在理解历史中标记为 system 来源。
