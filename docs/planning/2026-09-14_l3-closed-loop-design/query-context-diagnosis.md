# 2026-09-14 咨询短追问重复索要订单号

## 现象与证据

会话 `aec68146e4094116b54faf84a6b29ae2`：先输入「查物流 DEMO-X10-001」，收到 `shipped`；随后输入「物流状态」，系统回答「请提供订单号或物流单号」。

第二轮 `conversation_turn` 显示 `omitted_entries=0`，历史包含首轮订单号与物流答复；`qwen3.7-flash` 正确识别 `logistics_query`，且 `target_issue_id` 与前轮一致。问题发生在业务节点的参数承接，非本例的上下文裁剪或意图误判。

根因：成功查询后临时 `consult_params` 被清空；原实现下一轮只从本轮文本抽取标识符。开发中的上一版补丁仅支持「这个订单」等显式指代，也无法处理「物流状态」这样的省略追问。

## 修复

- `actions/params.py` 集中解析当前查询对象；本轮明确标识符替换整个旧对象，避免旧运单号与新订单号拼接。
- 没有新标识符时复用当前问题的查询参数、已核验凭证或执行回执。
- 旧检查点没有保存查询对象时，从同一问题的已处理用户记录恢复；不跨问题扫描。
- 明确要求另一笔订单但未提供编号时，清除旧查询引用，并阻止后续短追问从旧记录或凭证重新恢复旧对象。
- 咨询与服务上下文共用该解析入口；查询不会替代写操作的政策、凭证和用户确认校验。
