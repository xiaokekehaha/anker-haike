# 前置决策（L3 系列）

沿用 2026-09-12 系列 D1–D16 全部有效；以下为本系列新增。**标 ☐ 的两项需用户确认**，其余为默认采纳，反对请在此改。

| 编号 | 决策 | 默认 | 理由 |
| --- | --- | --- | --- |
| D-L3-1 | L3 业务系统全部用**模拟后端**（进程内适配器 + Postgres 演示表），接口按真实系统形状设计，可整体替换 | 采纳 | 赛题不提供真实系统；演示需可复现与故障注入 |
| D-L3-2 ☐ | 模型接入增加 **AWS Bedrock provider（lane=aws）**，默认通道仍 domestic；是否在演示现场切到 aws 通道待定 | 加 provider，通道待定 | 文档明示 AWS 能力可用；国内直连已 bake-off 达标，切换有回归成本；需要 AWS 账号与 key |
| D-L3-3 | **不使用 Bedrock Knowledge Bases**；检索继续 WeKnora + 自研 RRF / rerank / grade / 范围过滤 | 采纳 | 文档明确提示；现有链路可控可评测 |
| D-L3-4 | Step Functions **不用于会话级编排**；P2 可选用于案件级跨天定时（物流轮询、超时提醒） | 采纳 | LangGraph 的 interrupt / checkpoint / 事件流粒度是会话级需求；案件级长流程才是 Step Functions 的合适位置 |
| D-L3-5 | 政策判定、授权门、动作执行**零 LLM**；LLM 只做意图 / 参数抽取 / 措辞 | 采纳 | 幻觉难点的核心要求；可解释、可回放、可单测 |
| D-L3-6 | 政策规则为 YAML 演示规则，来源标「待真实 SOP 替换」；每条判定输出条款引用与版本 | 采纳 | 真实 SOP 未拿到；先把规则形状与引用链路做实 |
| D-L3-7 | 新增**案件（case）**对象，与 session / issue 分离；`done(completed)` 不等于结案 | 采纳 | 退换修与物流跨天；结案要客户确认 |
| D-L3-8 | 人工协同做**最小审批回路**：admin 队列 + 批准 / 修改 / 拒绝 + 决定回写会话恢复图；不做完整客服工作台 | 采纳 | 演示只需证明「人工决定成为可执行输入」 |
| D-L3-9 ☐ | 演示动作集：`logistics.query`（查物流）、`warranty.check`（查保修）、`replacement.create`（换货申请）三项 P0；`refund.create`、`address.update`、`rma.dispatch` P1 | 三项 P0 | 覆盖「30% 简单咨询」两项 + 「退换货方案决策」一项写操作；写操作一项足以演示授权门与回执 |
| D-L3-10 | 情绪从 3 级扩为 **4 级**（calm / dissatisfied / angry / complaint_risk）+ 轨迹；策略矩阵配置化 | 采纳 | 文档要求分层分级；「投诉」不再是关键词直升级 |
| D-L3-11 | 看图输出改为**结构化故障定位**（部件 / 位置 / 现象 / 严重度 / 置信）+ 图片可用性；不可用发补拍卡（可跳过） | 采纳 | 文档「看图」的核心是提取而非识别 |
| D-L3-12 | 多意图**顺序处理**，优先级固定（安全 > 人工 > 办理 > 排障 > 咨询 > 闲聊），系统告知顺序并在当前任务结束后自动接续 | 采纳 | 并行处理会打乱一次一卡的等待模型 |
| D-L3-13 | 简单咨询走**独立快路径**，不进 disambiguate / retrieve；缺参数用文本追问并计入澄清次数 | 采纳 | 30% 场景不该被排障流程拖慢 |
| D-L3-14 | 三项基线在管理台落为指标：托管率、意图准确率（离线 + 在线抽样）、NSS（5 分制换算） | 采纳 | 没有指标就无法对标 |
| D-L3-15 | 多品类、真实工单管线、多语言、多模型交叉审核放 **P1/P2**，P0 仍以扫地机为演示品类 | 采纳 | 真实数据 schema 未知；先把链路做通 |
| D-L3-16 | 契约改动一次性在票 51 完成并重新生成 TS，其余票不再改 Literal | 采纳 | 避免前后端漂移反复 |
