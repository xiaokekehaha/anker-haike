# 情绪、人工请求与设备安全分流

P0 61 的真实 A8 演示暴露了两个语义职责混用，按用户要求从接口和流程处理。

## 原因与改动

原意图没有“表达不满/投诉”这一项，模型会把平台投诉归成 request_human，触发 R3 并撤掉原卡片。新增 complaint 意图，情绪策略与接入人工请求分别表达。自由文本转人工须带当前用户原话 human_request_quote；缺少来源时不能仅凭分类器建议撤掉任务。用户点击转人工按钮的已验证命令保持有效。

第二次诊断发现，通用名 risk_assertion 被模型用于表达投诉风险，误创建 R4 设备安全记录。语义接口改为 device_safety_assertion/device_safety_quote，明确只表示设备与人身物理安全；投诉风险仍由 emotion_level/emotion_cues 持有。解释器版本升为 2026-09-14.8，同步更新会话样本与巡检解释器。已有 R4 规则预检查和风险未解除时的限制保持有效。

降级解释器沿用 R3 规则识别明确人工请求，并输出原话；无其他业务诉求的不满或投诉进入 complaint。失败回放另存诊断记录，包含语义输出和实际阶段，不生成成功包，避免只能重复调用模型猜原因。

## 验证

会话归约、恢复、全局人工入口、L3 相关检查 44 passed，Ruff 通过。A8 真实模型录制与格式 3 离线回放通过：dissatisfied → angry → complaint_risk；第三轮收集必要服务信息，进入方案与人工审核，没有误触发 R3/R4。模型命中 7、知识命中 2、未命中均为 0。

证据：`replay/a8_emotion/`、`reports/inspection/l3/emotion-routing-validation.json`。这验证了本次明确场景与关键不变量，不代表所有自然语言表达都已覆盖。

解释器契约已改变，此前在 .6 录制的 A4/A6/A7 和 .1 动作配置的 A5 不能充当当前版本发布证据；待语义改动稳定后统一更新，避免中途反复录制。
