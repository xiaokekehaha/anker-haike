# 物流查询执行约束

## 问题

物流主诉求已经识别，但 answer_request 附带购买信息时，consult 可能只读订单并逐字段回复，漏掉物流状态和 SOP 方案。现有未提交补丁用订单关键词决定是否删除非物流字段，会误伤混合查询，也无法可靠区分背景和提问。

## 方案与范围

1. 检查 consult、任务队列和答案字段的职责及现有测试。
2. 以物流诉求驱动必需的物流查询及 SOP 回复，保留附加字段答案，不以字段纯度决定是否提供物流方案。
3. 保留查询对象不匹配保护、用户确认和既有待处理卡片边界。
4. 用离线回归覆盖背景字段、含收据关键词、混合金额查询、查询对象不匹配与已有卡片。
5. 执行相关测试和 make lint，记录修改范围、结果与剩余限制。

## 边界

不修改其他会话的无关改动；不提交、不发布。本次解决执行层漏答，不把背景事实归属的语义识别准确率宣称为已修复。
