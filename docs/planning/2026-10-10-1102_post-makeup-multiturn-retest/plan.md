# 容器重建后的四案复测

## 目标

用户已执行 make up，要求继续验证此前四个多轮问题是否已修复，并以中文报告当前问题和回答。

## 方案

1. 核对服务健康、容器身份、当前工作区与容器中业务源码及配置的指纹。
2. 使用原官方工单、原附件和固定模拟回复，分别重跑 T22、T46 卡片答案、T46 文字答案、T52、T48 五条路径。
3. 每条路径以独立新会话运行两次，保存全部原始事件、快照、实际检索和最终发布状态；如首轮边界变化，记录后续是否实际到达。
4. 按用户指出的具体症状判定，不以接口成功、不同措辞或没有报错代替业务验证。
5. 交付中文问题与回答记录，区分原症状修复、新问题和证据不足。

## 约束

- 本次只验证，不修改业务实现，不提交、发布或重建容器。
- 不覆盖其他任务已有修改和文档。
- 真实服务运行不属于单元测试，不通过 tests 模块启用模型或知识库。
- 临时执行器写入临时文件并在完成后删除；密钥不进入文档和日志。
