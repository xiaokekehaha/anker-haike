# 赛题解析文档要点（比较材料）

来源：飞书文档《Anker首届黑客松挑战赛·9月9日赛题解析直播资料包-智能服务赛道》（RYK1wZt8cit813kK4nxc138znie，作者 grace.hu / julia.tang，2026-09-09 修订）。2026-09-14 通过已登录浏览器读取全文五节；下面是原文要点的归纳，不是逐字转录。

## 1. 三阶段框架与定位

| 阶段 | 含义 | 原文判断 |
| --- | --- | --- |
| L1 问答 | 从知识库里找答案 | 行业基本成熟 |
| L2 引导 | 多轮追问、收集信息、一步步引导操作 | 各家参差不齐 |
| L3 闭环 | 调用后端系统把事办成：退款、换货、派单 | 真正难的部分；安克已具备，仍在深化 |

一句话定位：由大模型驱动、**独立接住每一次求助并从头到尾办成**的智能客服；考察的是整条售后业务处理链路，不是 L1/L2 对话机器人。

## 2. 对标基线

- 独立托管率 70%–80%
- 意图识别准确率 90% 以上
- 用户净满意度 NSS 60% 以上（与真人客服持平）

## 3. 场景比例与五个难点

30% 简单咨询（查物流、查保修、改地址）；70% 复杂售后（多品类故障诊断、多平台 + 多区域质保政策确认、退换货方案决策）。五个仍在攻克的难点：

1. **看图**：重点不在识别而在识别后的信息提取，要能精准锁定故障位置。
2. **问清**：客户主观、口语化描述 → 精准识别故障类型。
3. **分流**：一句话混杂多个需求；同一产品在不同渠道/国家的服务策略差异 → 精准路由到对的流程。
4. **接稳**：情绪程度分层（不满、暴怒、投诉风险递进），要用不同策略接，不是一套话术。
5. **幻觉**：售后致命伤；面对复杂规则与流程要**按设计的策略和流程执行而非自由发挥**，不产生不合规回答。

## 4. 技术边界

可拿到：脱敏工单数据集、产品技术知识库、授权经销商名录、业务 SOP 规则；AWS 的多模态理解、LLM、Embedding、向量检索、Step Functions。技术路线自选（FAISS、Chroma 等）。

不能碰：只换提示词的 FAQ 机器人；伪造排障结果、虚构质保承诺、编造召回答案（检索不到就诚实升级）；采集或留存真实用户隐私。

提示：建议**不要直接套 AWS Bedrock Knowledge Bases**，它把切片、向量化、检索、重排封成黑盒，无法做精准召回策略。

## 5. 评判口径

每个难点处理得有多深、多实：图看得懂、关键信息提取准；意图准、路由对、规则严谨（能「担起责」）；情绪分层分级处理；业务办理既流畅又准确，该办的办成、不该办的绝不乱来。交付形式：现场可交互演示，不是 PPT 或视频。
