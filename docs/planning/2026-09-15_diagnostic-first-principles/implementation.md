## 改动结果

| 原机制 | 实施后的行为 |
| --- | --- |
| 同时用词面长度、症状码、问答状态判断症状是否明确 | `diagnose/decision.py` 统一读取当前问题的原始事实与已接受答案；词面匹配只提供正向补充，不否决已有语义证据 |
| 历史“不开机”编码覆盖新“不充电”回答 | 两种信息同时保留；追加症状不撤销旧答案，显式纠正才让相关推断失效 |
| 连问两次就按无法理解转交 | 先应用答案；若剩余可能性拥有同一套适用计划，直接检查；无有效答案或没有可区分问题才停止。产品确认兜底仍保留，但不继承症状追问次数 |
| 操作文案可以经模型改写，自由问答可以提出额外操作 | 操作原文发布，停止条件独立展示；诊断解释、历史回顾使用当前步骤和真实记录，不能创建新动作。停用步骤改写的模型评测与成本项 |
| 计划中的风险词可以写入设备风险状态 | 删除遗留的源文案创建风险分支；危险/不适用的操作正文只会被丢弃，用户实际报告的风险仍触发 R4 |
| “不开机/不充电”没有适用计划 | 增加 `rv_power_supply` 两步：外部供电/触点观察、回站观察充电。原文来自现有 `troubleshooting_rv.md` E 节，并附来源版本 |
| 排障失败自动要求购买凭证 | 无办理诉求时直接整理摘要；明确的换货、退款等诉求继续进入既有业务流程 |
| 摘要后追问可绕过步骤限制或重开已完成操作 | 未结束的步骤保持待反馈；已解决或已耗尽时解释状态。原 R7 会话可按已保存答案恢复继续判断 |
