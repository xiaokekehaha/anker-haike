- 多品类计划声明 7 个深度品类，其他品类以目录识别为主；质保规则仍仅扫地机。
- 最近提交还包含照片症状进入诊断、范围外产品切换、品类级手册与可审计引用。
- 后续必须区分：目录识别、知识检索、可执行排障、售后执行四种覆盖，不能用 in_scope 单字段代表全部能力。
- 用户确认评审范围；code-review 要求的规范 / 需求两轴已分派两个只读子任务。
- 补充信息来自仓库 9/14 赛题解析归纳；旧 gap-analysis 的“L3 零覆盖”已过时。当前具备动作注册、授权、执行回执、案件与人工协作骨架。
- `KnowledgeScope.region` 已存在，但 `IndexEntry` / `allowed_entries` 未消费区域与发布状态；导入也不保留 source/region/publish_state。
- `PolicyLoader.validate` 强制 `source == demo`，`applies_to` 只允许品类 / 购买地区 / 渠道；真实来源、SKU 特例、平台、生效时间还需扩展。
- `actions/runtime.py` 只装配 MemoryBackend / MockBackend；注册动作仅物流查询、质保查询、换货。真实材料交付与真实业务接口接入是两项独立工作。
- 经销商以名称唯一，lookup 不使用地区，缺平台、别名、有效期；导入真实名录需先升级身份键。
- `ingest.upsert_manual` 按 title + doc_version 去重，版本变化先删旧建新；需要稳定 doc_id / 内容哈希、预检与批次发布，避免直接覆盖演示库。
- 精确覆盖：20 品类 = 7 排障 + 12 目录 + 1 范围外；57 SKU；32 计划；9 手册 + 7 FAQ + 380 合成工单。
- 知识检查新增发现：缺失手册在 FAQ 关闭时记 skipped_faq_off；no_chunks 也不判失败。主引用仅比较文档与锚点，不验证文档版本 / 原文，因此旧步骤可挂新版引用。
- 离线合成复现以上两问题，以及区域 / draft 过滤缺失、真实 source 被政策拒绝、同版本正文漂移被跳过；所有运行不调用真实模型或知识库。
