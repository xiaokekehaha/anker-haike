# 主办方资料包对照与重新规划（2026-10-07）

事实依据见同目录 `findings.md`。本文说明三件事：资料包改变了什么、现有实现哪里对不上、接下来做什么。

## 0. 结论

主办方给出了明确的 **SOP 主干、真实工单和真实知识库**。评委会拿这 63 单检验我们是否按 SOP 走对了分支。我们原先的设计是在没有数据的情况下自己推断的，有三处与资料包相反：

1. 业务数据全部要换掉。我们的知识库是中文合成手册，覆盖 60 个产品；资料包是 875 条英文 Q&A，覆盖 8 个产品，并且以错误码 + PN 为索引。
2. 渠道和语言不同。我们只支持中文聊天；资料包的工单是英文和荷兰语等多语种邮件，约一半是 App 自动生成的结构化报错（带 Problem Code）。
3. 质保与动作语义不同：
   - 质保：我们按美国政策条款推算质保期，非美国订单一律转人工；资料包的订单直接给出质保结束日期，SOP 里没有地区判断。
   - 动作：我们的换货是自主执行，并承诺「3 个工作日发出」；主办方要求工具只负责提交换货单或退款单，然后转人工。

可以保留的部分：LangGraph 编排、分步排障卡、授权闸门、凭证 OCR、产品消歧、情绪模块、后台与评测框架。这些正好对应资料包里的真实场景，例如 S1 Pro 扫地机与吸奶器同名、凭证截图来自 Amazon、Aeroflow、发票，以及辱骂类工单。

## 1. 主办方要求的流程（我们要对齐的目标）

```
首封消息（邮件 / App 报错 / RMA 表单，多语种）
   |
   v
意图：物流 / 故障排查（含产品咨询）
   |
   +-- 物流 --> 查订单 + 包裹轨迹
   |              显示送达            --> 告知送达信息，不补发
   |              未送达且客户未收到  --> 补发单 --> 转人工
   |              预售未发            --> 告知预计发货日期
   |
   +-- 故障 --> 知识库检索 + 排障（错误码精确命中优先）
                  已解决 --> 结束 + 满意度调查
                  未解决 --> 是否进入换货 / 退款
                               |
                               v
                         订单质保判断（看订单的质保结束日期）
                   查不到           质保期内          质保期外
                     v                 v                 v
              问购买商家与国家     收集证据          告知过保并委婉拒绝
              查经销商名录        （凭证 / 地址 /
              授权 --> 走质保内     照片或视频 / SN）
              未授权 --> 引导       换货或退款单 --> 转人工
              找商家售后
```

## 2. 差距清单

严重度说明：

- **阻断**：不改则真实工单直接跑错分支或无法处理。
- **偏差**：能跑，但结果与 SOP 不一致。
- **加分**：SOP 之外的展示点。

## 3. 规划

按依赖关系排序。每一步做完都用 63 单评测集回归一次。

### P0 数据底座（与需求变化无关，先做）

1. **导入主办方数据**，新增一个导入命令：
   - 订单：多包裹、质保结束日期、物流状态枚举。
   - 经销商：336 行，做名称归一化。
   - Q&A：875 条，导入 WeKnora，同时建错误码与 PN 索引。
   - PN 目录：从订单和 Q&A 生成。
   - 原合成数据移出默认种子。
2. **63 单评测集**：
   - 每单标注：期望意图、期望 SOP 分支、必须回复的语言、禁止出现的承诺（例如已送达的包裹不得承诺补发）。
   - 先做确定性评估：解析、分支、工具调用；再做模型抽检。

### P1 SOP 主干

3. **首封消息解析**：App 报错 / RMA / 自由邮件三种格式的确定性解析，加语言识别。
4. **回复语言**：客户可见的输出全部跟随客户语言。
5. **物流分支**：
   - 送达 → 不补发。
   - 未送达且未收到 → 补发单。
   - 预售 → 告知预计发货日期。
   - 数据与客户描述冲突 → 按 D3 处理。
6. **质保分支**：
   - 有订单 → 读质保结束日期。
   - 查不到订单 → 追问商家与国家 → 查经销商名录。
   - 过保 → 委婉拒绝。
7. **证据清单与服务单工具**：
   - 换货 / 补发 / 退款都走「提交服务单 → 转人工」。
   - 授权闸门改为检查四项证据。

### P2 质量与演示

8. 英文情绪、安全规则与用例。
9. 演示案例：每个 SOP 分支配一张真实工单（D6）。
10. 前端加「载入工单」入口：选一单真实工单作为首封消息，演示和回归共用。

可选复杂度（不做也不影响 SOP 对齐）：多诉求分流、设备照诊断、百炼部署。

## 4. 评测指标（与赛事基线对应）

| 指标 | 定义 | 基线 |
| --- | --- | --- |
| 意图识别准确率 | 物流 / 排障 / 换货 / 退款 / 咨询，以 63 单标注为准 | ≥90% |
| SOP 分支准确率 | 送达不补发、过保拒绝、查不到订单时追问商家、安全问题转人工等分支是否走对 | 新增 |
| 独立托管率 | 不转人工就闭环的比例。注意「提交服务单后转人工」是 SOP 规定的终点，应单独统计，不计为托管失败 | 70–80% |
| 幻觉 | 编造物流状态、承诺补发或换货时效、套用知识库未收录的错误码（T13 的 5116） | 0 |
| 语言一致 | 回复语言与客户语言一致 | 100% |
