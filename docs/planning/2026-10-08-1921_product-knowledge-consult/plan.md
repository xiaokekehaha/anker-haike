# 产品使用咨询修复方案

## 问题与目标

产品使用问题被统一归为 explain，进入只解释聊天记录的路径。已有型号与官方知识因此没有被使用。修复应保存用户咨询目标，按缺失信息追问型号，并在型号确认后使用官方知识回答。

## 设计约束

- 产品使用咨询与已有步骤解释分开建模；不能靠某个功能关键词专门处理。
- 保存原始咨询问题与来源，补型号后继续原问题。
- 复用产品目录、知识适用范围过滤、引用与安全规则。
- 不把普通功能咨询转成故障症状追问或步骤反馈。
- 知识不可用和无匹配如实说明；不由模型补造说明。
- 维持问题之间的设备与状态隔离，避免吸奶器 S1 Pro 与扫地机 S1 Pro 混用。
- 不改其他会话正在修改的 contracts 及其生成文件。

## 实施顺序

1. 完整读取将修改的代码，确定最小模块接口和状态保存位置。
2. 用假模型与假知识库建立先问功能、后补型号的失败回归测试。
3. 实现产品咨询语义、任务保存、型号确认、检索和证据回答。
4. 验证直接咨询、同名消歧、无匹配/不可用、原有步骤解释等相关行为。
5. 运行 make lint 与相关测试，记录结果；不提交。

## 验收

原始功能问题缺型号时追问，用户补充 T8D04 后检索仍包含原始功能问题，按 T8D04 过滤并使用 bp-0001 证据回答。不得将补充型号作为唯一查询，也不得虚构诊断动作或把用户补充型号当作操作反馈。
