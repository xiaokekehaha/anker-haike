# 官方支持资料采集与入库

适用：当前 Anker、eufy、soundcore 官方支持站的公开文字文章。首批已实际采集并入库，详见 [验收报告](../planning/2026-09-17_official-knowledge-collection/report.md)。

## 接入流程

1. 在 `data/knowledge/sources/anker_official.yaml` 增加官方文章 URL、稳定的 `id`、产品名称、品类和 SKU。先核对官网型号与 `config/products.yaml`；同名产品不能跨品类绑定。每个技术问题写一个 `units` 条目，保留适用前提、完整操作和必要注意事项，并提供一条自然语言验收问题。
2. 执行 `make kb-official-fetch`。采集器只从官方页面的文章字段提取正文，不采导航、广告和相关推荐。原始 HTML、提取文本、采集时间与哈希写入忽略目录 `tmp/official-knowledge/`。公开页面重定向、结构变化、空正文会停止本次采集；不会绕过登录或访问控制。
3. 对照缓存原文复核中文摘要。`anchor` 是原文定位词，存在定位词不等于事实已审核。核对后将正文 SHA-256 填入 `reviewed_source_sha256`；更新资料时递增批次 `version`。不要在来源变化后自动替换哈希而跳过摘要核对。
4. 首次生成新一批文件前执行 `make kb-snapshot-export`，保留包含原有本地源文件和远端清单的快照。执行 `make kb-official-build`：校验来源哈希、SKU/品类、语义单元长度，全部通过后生成 `data/knowledge/kb_manual/official_*.md`。这些文件由来源清单生成，修改摘要应改 YAML 后重建。
5. 执行 `make kb-ingest`。该入口会再次自动导出快照，按文档 ID / 标题和版本导入，生成 `manifest.json`。正常补充资料不传 `PRUNE` 或 `RECREATE_KB`。现有入口也会按本地源文件整体同步 FAQ，因此执行前应检查是否有其他会话正在修改知识源。
6. 执行 `make kb-official-verify`。每篇文档必须已解析、元数据完全一致、每个语义单元完整位于至少一个实际子块中，且对应问题的前 5 条结果包含该单元。再检查已确认型号可见，其他型号、其他品类、未确认型号不可见。失败时退出码非零；报告写入 `reports/knowledge/`。
7. 业务编排进程只在首次使用时拉取知识索引。已缓存索引的进程需刷新索引和块缓存，或随下一次受控重启重新加载。新开的验收适配器通过不代表旧业务进程已更新；入库本身不需要发布新应用镜像。

## 切分约定

- 先按问题整理语义单元，再交给 WeKnora 切块。每个单元包含产品名、问题标题、稳定的 `cN` 锚点和中文操作摘要；完整单元不得超过 200 字符。超出时按独立操作重新组织，不能截掉末尾的前提或注意事项。
- 当前库沿用父块 800 字符、子块 200 字符、配置重叠 80 字符，优先按空段、换行、句号等边界切分。父块用于补上下文，子块用于检索。语义单元与子块不要求一一对应；两个短单元可以完整地落入同一个子块。
- 参数只是目标，必须回读真实子块验收。本批 24 个语义单元实际生成 23 个子块，每个单元的产品名、锚点和完整摘要都能在单个子块找到。
- 网页表格应按一项故障及其完整处理条件组织；不能将表头和数值、错误码和处理方法拆开。当前采集器不解析 PDF、扫描图或视频；此类资料需要独立解析和人工核对后再进入相同的语义单元与验收流程。

## 来源、版本与限制

- 发布内容是依据英文官方文章编写的中文摘要，`source_type=official_support_summary`，不是官方中文原文或完整手册。原始页面只保存在本地忽略目录，仓库保留事实摘要、来源 URL 和哈希。
- WeKnora v0.8.0 的 `custom_metadata` 最多 20 个字段，数组转换为逗号分隔标量。本批保留文档 ID、范围、SKU、品类、版本、知识库类型、来源类型/URL/标题/语言、摘要语言、来源和正文哈希、采集时间、批次、发布状态、核对状态、适用说明、地区列表和章节列表，合计 20 项。
- 来源正文、摘要或适用范围变化都会改变文档版本；仅重新采集的时间变化不会重复生成向量。稳定 `doc_id` 可避免来源标题修改后保留重复旧文档。每轮资料变更仍须递增批次 `version`，使总库版本明确变化。
- `review_status=agent_source_checked` 表示本次代理对照来源核对，不表示业务人员或厂家审批。知识内容不能自动变成退款、换货、诊断或配件发放权限。
- 当前检索过滤实现覆盖型号和品类；地区、发布状态字段尚未接入运行时过滤。本批只放已核对的型号技术资料，不放地区质保、召回、航空运输或医疗结论。后续政策资料必须先补相应范围与状态过滤。
- 现有演示手册与工单仍在库内，本批以 `official_` 文档 ID 和来源字段区分。新资料不会自动覆盖演示计划里的旧证据锚点；计划引用迁移需要单独核对。
- Space One 目前属于目录级品类：已可按 SKU 检索资料，但新增知识不等于该品类已有完整的可执行排障计划。

## 本地验证

```bash
make lint
cd orchestrator
uv run pytest -q --show-capture=no tests/test_knowledge_official.py tests/test_knowledge_ingest.py tests/test_knowledge_adapter.py
```

默认单测使用内存版 WeKnora，不连接真实知识库。真实批次验收通过独立的 `make kb-official-verify` 执行，会调用现有检索和向量服务。
