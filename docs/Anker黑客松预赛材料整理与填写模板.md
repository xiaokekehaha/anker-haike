# Anker首届黑客松挑战赛 预赛材料整理与填写模板

## 编写与提交要求

预赛材料需要让评审快速理解：要解决什么问题、为什么值得解决、准备如何实现，以及团队能否在24小时内完成可演示原型。核心内容是赛题理解和解决方案，宜简明具体，集中展示2–3个核心功能。

### 原文要求摘要

| 项目 | 要求 |
|---|---|
| 提交时间 | 9月27日23:59前；原文未标明年份 |
| 提交方式 | 在预赛提交问卷中提交方案文档链接 |
| 链接权限 | 提交前开启“互联网获取链接可阅读权限” |
| 团队规模 | 2–4人，含队长；队长为官方唯一联系人 |
| 意向赛道 | 智能录音、智能安防、充电储能、智能服务 |
| 必须内容 | 预赛信息卡；赛题理解；具体方案；价值与预期效果；优势与创新点 |
| 原型要求 | 说明24小时内可做出的可演示原型；预赛材料不要求提供Demo、代码、完整立项文档或架构说明 |
| 可选内容 | 架构草图、迭代规划、参考资料、项目经历、获奖证明、团队详细介绍等 |

### 评审关注点

- **选题明确度：** 目标用户和痛点具体，抓住真实业务场景的核心问题。
- **方案清晰度：** 说明功能做什么、怎么做、为什么这样做，技术路径可行。
- **项目创新性：** 体现AI Native思路和差异化，可从需求、解决思路或技术展开。
- **落地可行性：** 范围与团队规模、24小时开发时间相匹配。
- **团队能力匹配：** 成员技能与任务相符；原文强烈建议附过往作品链接，属选填。

### 使用方式

后续章节可作为填写稿。将【待填写】替换为实际内容；第3个功能及自由展示区按需保留。提交前删除本页编写说明及所有填写提示，检查姓名、联系方式、链接和材料完整性。原文评分参考表也要求在提交时删除。
