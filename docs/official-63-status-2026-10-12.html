03

系统怎样回答一单

先保留客户原话和事实，再决定业务路径；每一步都要知道“还缺什么”。下图是目标流程，旁边标注当前证据。

1. 理解输入表单 / 邮件 / 图片
识别诉求、对象、否定与已做事实
2. 检查边界安全优先
多任务排序，缺信息先澄清
3. 执行业务查物流 / 精确码 / 知识候选
前提核对，再提供步骤或说明
4. 明确下一步等真实答案 / 核资格 / 客户确认
必要时交人工，保留未答问题
  1. 确认订单与包裹对象

    缺号码先收；主机与配件记录冲突时保留两份说法。

  2. 依据记录选择物流分支

    已送达：说明并可调查；退回 / 逾期：提出补发；预售：说明原计划日期。

  3. 客户确认后提交，由人工办理

    方案卡不是补发完成；暂停与取消也需实际人工处理。

主干有证据

T9：暂停申请与物流都保留

暂停进入人工队列，同时说明主机预售及滤芯已送达。没有把“已申请暂停”说成“暂停成功”。

仍需关注：T6 语言适配；历史商家背景的事实归属。物流字段修复只证明主流程不被附加字段挤掉。[S2][S7]

  1. 先确认型号与具体现象

    只说“效果差”先澄清；只说一侧正常，不替客户指定坏的一侧。

  2. 找资料，并核对是否适用

    有码先精确匹配；未收录不套相近码。语义候选核对部件、时机和前提。

  3. 核对已做事实，再发卡

    问句等真实答案；部分已做说明剩余部分；未解决沿分支继续。

  4. 指南耗尽，说明原因并进入售后

    说明尚未查明的症状，不把索凭证当成已经解释根因。

步骤与事实仍有波动

T40 改善；T51 仍跳错步骤

缺链指南不再直接封死其他候选；但“充过电”仍可能被当成“已经充满”。

必要修正：逐字引文存在，只能证明客户说过这句话；还必须判断这句话是否真的足以完成该步骤。[S3][S6]

  1. 确认购买记录与资格

    有订单读质保结束日期；无订单先收凭证 / 商家 / 国家，再按项目规则核验。

  2. 按资格进入对应分支

    过保说明常规边界；保内继续收订单或凭证、地址、故障媒体、序列号。

  3. 确认方案 → 提交服务单 → 转人工

    核资格前不承诺更换，未实际提交不说已经办理。

观察停点不等于最终办理

T55：只收缺少的材料

保内继续收故障媒体与序列号，没有重复索已提供的购买凭证。

待核：T53 主张保内发生故障、过保才申报。常规日期计算不能替代官方例外政策与人工审核。[S1][S2]

  1. 确认型号；有图先读图

    位置、颜色、常亮 / 闪烁分别确认，单帧照片不能证明动态灯态。

  2. 按官方资料解释

    有答案给依据；资料不足明确缺口，不从颜色常识猜产品含义。

  3. 缺答案时给出下一步

    继续澄清，或交技术核查，并保留真正要回答的问题。

读图改善，答案仍缺

T48：看到灯，不等于解释灯

本轮已读图，检索 15 条结果仍没有绿灯定义；只列红灯资料，后续澄清 / 核查入口不明确。

必要工作：把官方分型号灯态图转为可检索内容；还要收灯位置和动态状态。[S2][S3]

  1. 识别交人工的真实理由

    客户明确要求、安全风险、知识缺失、办理权限不足等分开记录。

  2. 保留每项诉求与证据

    采购对象来自采购原话；故障事实不能替代购买对象；记录缺少的型号与材料。

  3. 如实报告提交状态

    已整理、已提交、已接单不同；人工接手不自动免除其他问题的解释义务。

边界正确仍可能答不全

T63：刷罩正确，问题还没承接完

定向回放 3/3 交接为 brush guard；但型号、断卡扣、胶带固定、清扫表现仍需收集和交接。

另一个边界：T20 无危险观察不应触发安全转人工；T45 明确烫伤仍应停止操作。[S2][S4]

知识库在工作，但检索成功不等于回答充分。 27 案有检索记录，共 55 条：53 条成功，2 条在型号未确认、允许文档为 0 时无匹配。其余 36 案包含本地错误码匹配、订单、安全和资格路径，不能全部算作“未用知识”。[S2]
