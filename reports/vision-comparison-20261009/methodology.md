# 评测方法与边界

评测日期：2026-10-09，北京时间。目标是比较本项目图片输入上的表现，不生成通用模型排行榜。

## 输入与任务

- 5 张官方实物照片：T14、T20、T30、T42、T48。
- 5 张官方凭证截图：T38、T45、T46、T53、T55。
- 3 张现有套件的合成铭牌：34px、22px 低对比度、14px 低对比度。
- 同三张铭牌的右下九宫格裁剪，复用 `app.images.prepare.crop_cell` 的默认外扩、放大参数。位置由评测者预先给定，不评价自动定位。
- 每个样本每个候选调用两遍，额外接口预检不纳入统计。

输入的路径、SHA-256、标准答案和完整提示词保存在 `manifest.json`；新增模型和补充任务保存在对应 `*-manifest.json`。标准答案不发送给模型。官方附件原样发送，未附带工单描述、产品目录或聊天历史。

实物照片任务要求图像类型、设备品类、可见指示灯、裂纹、烟雾/烧灼证据和可直接读出的具体型号。根据图片选择适用字段，共 24 个预设检查项，重复两遍共 48 项。T42 是局部图，输出 unknown 计为未识别，但属于保守弃答，与断言错误品类不同；不能将总失分等同于幻觉次数。没有正向烧灼样本，不能用本轮阴性检查评价安全召回。

凭证有两种任务：第一种要求转录全文再抽字段，第二种仅抽订单号、销售方、日期、总额。第二种更接近本项目实际需求，但仍是独立提示词，不是整个线上工作流。不要把全文转录截断率当成生产字段抽取失败率。

## 候选与调用

| 候选 | 接口模型 ID | 参数 |
| --- | --- | --- |
| DeepSeek | deepseek-flash | thinking=disabled，temperature=0 |
| Qwen-VL | qwen3-vl-plus | 项目配置，temperature=0 |
| GLM 旧视觉模型 | glm-4.6v | thinking=disabled，temperature=0 |
| GLM 新多模态模型 | glm-5.3-flash | thinking=enabled，temperature=1，top_p=0.95 |
| GLM-OCR | glm-ocr | layout_parsing 默认参数，只参加文字任务 |

聊天接口都使用 `response_format=json_object`，原三家输出上限 2048 token。GLM-5.3-Flash 按官方约束只能开启思考，输出上限放宽至 8192，未指定 reasoning_effort，保留服务默认值。因此不是相同推理预算下的比较。HTTP 单次等待上限 60 秒；不自动重试，不切备用。各厂商串行处理同一候选，智谱跨实验最大并发为 2。

GLM-OCR 返回 Markdown/HTML，不接受相同聊天提示词，也没有业务四字段的语义解析。这是官方默认托管 API 的实际效果比较，不代表其开源权重自部署效果。原始结果记录用量和延迟，不记录认证头、请求图片 base64 或密钥。

## 评分

- 字段检查：空值和布尔值严格匹配；文字忽略大小写、空白和标点后完整匹配，保留全部字母数字；金额按十进制数值匹配。缺少字段不等于正确留空，输出缺失或失败记错。
- 铭牌型号正确率：要求完整匹配 X10 Pro，不能把留空或其他貌似合理型号判对。
- 关键文字覆盖：检查转录文本是否包含完整目标片段，大小写、空白、标点和 HTML 标签不影响；不是全页字符准确率，也不检验额外编造。每份凭证 4 个片段，每张铭牌 4 个片段。
- HTTP 成功、完整输出、字段正确分别统计，HTTP 200 但截断不能算完整结果。
- 延迟为本机从发送 HTTP 到接收响应的总耗时，取中位数，不是首字延迟，不含故障回退或人工确认。

字段与文字覆盖不能覆盖所有自由文本错误。因此逐条检查了关键反例，并在报告中另列编造、遗漏和弃答。

## 历史报告的使用范围

历史 baseline（65%/80%/69%）和 stage4（96%/93%/91%）来自不同业务实现与提示词，并且主要使用合成图。不能与本轮直接比较为模型提升，也不能作为真实图片准确率。旧 scorer 对订单号删除字母、接受子串；本轮未使用该宽松规则。旧 runner 的硬门原因可能被后续清空；本轮不采用自动主备裁决。
